# 第 31 课：为状态解析加入可重复检查

- 日期：2026-10-21
- 课程序号：第 31 课
- 知识点：check 验证固定输入契约

## 用途或适用场景

让成功状态与失败原输入都能在一次运行中检查。

## 核心概念

check(false) 抛出 IllegalStateException，适合本课的程序内契约检查；它不依赖 JVM 是否启用 assert。解析仍精确匹配名称，不规范化用户输入。

## 最小代码或操作示例

在第 30 课 parseStatus 之后、main 外新增，并在原 main 末尾调用 checkStatusParsing()：

```kotlin
fun checkStatusParsing() {
    when (val result = parseStatus("DONE")) {
        is StatusParseResult.Success -> check(result.status == LessonStatus.DONE)
        is StatusParseResult.Failure -> error("DONE 应解析成功")
    }
    for (inputName in listOf("ready", "")) {
        when (val result = parseStatus(inputName)) {
            is StatusParseResult.Success -> error("无效名称不应成功")
            is StatusParseResult.Failure -> check(result.inputName == inputName)
        }
    }
    println("三项解析检查完成")
}
```

check 核对布尔契约，error 在不应到达的分支抛错；不捕获这些检查失败来输出完成。原 enum/parseStatus 均保留。

## 3～5 分钟练习

在练习副本把第一项期望状态改成 READY，运行后恢复。

## 参考答案

改错时在第一项抛 IllegalStateException，不能到达完成提示；恢复后 DONE、ready、空串分别满足成功和两项失败契约。它仍是普通运行入口，不是测试框架报告。
