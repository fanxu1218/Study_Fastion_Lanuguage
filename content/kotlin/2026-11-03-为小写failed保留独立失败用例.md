# 第 40 课：为小写failed保留独立失败用例

- 日期：2026-11-03
- 课程序号：第 40 课
- 知识点：合法名称与小写输入的精确边界

## 用途或适用场景

防止FAILED合法行的加入意外放宽解析规则。

## 核心概念

原FAILED合法不代表小写failed合法。失败结果保留原输入，调用方数量独立更新，不能用大小写归一化改变已学契约。

## 最小代码或操作示例

沿第38课READY和第39课FAILED合法行，在checkStatusParsing的cases原八行后追加：

```kotlin
StatusParseCase("lowercase-failed", "failed", StatusParseResult.Failure("failed")),
```

main把原数量检查替换为：

```kotlin
check(checkedCount == 9) {
    "完成数量不符：期望9，实际${checkedCount}"
}
```

沿原Kotlin1.9+项目和逗号格式；逐行check、循环后的return cases.size及函数一次调用保留。

## 3～5 分钟练习

把Failure("failed")误写成Failure("FAILED")会发生什么？

## 参考答案

data class内容比较应失败，消息指向lowercase-failed。输入必须保持原样；不能在parseStatus里转大写迎合期望。
