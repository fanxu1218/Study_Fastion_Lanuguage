# 第 32 课：为状态解析检查增加具名用例

- 日期：2026-10-22
- 课程序号：第 32 课
- 知识点：用已有 data class 保存输入与固定期望

## 用途或适用场景

让一次检查失败能指出对应输入用例。

## 核心概念

具名表行保存独立期望结果；Success/Failure 已是 data class，可以比较其内容。名称用于测试诊断，不参与 parseStatus 的精确匹配。

## 最小代码或操作示例

沿第 31 课，在 parseStatus 后、main 外新增：

```kotlin
data class StatusParseCase(
    val name: String,
    val inputName: String,
    val expected: StatusParseResult
)
```

将 checkStatusParsing 替换为：

```kotlin
fun checkStatusParsing() {
    val cases = listOf(
        StatusParseCase("done", "DONE", StatusParseResult.Success(LessonStatus.DONE)),
        StatusParseCase("lowercase", "ready", StatusParseResult.Failure("ready")),
        StatusParseCase("empty", "", StatusParseResult.Failure(""))
    )
    for (case in cases) {
        check(parseStatus(case.inputName) == case.expected) {
            "解析检查失败：${case.name}，输入=[${case.inputName}]"
        }
    }
    println("三项解析检查完成")
}
```

原 main 调用、枚举和 parseStatus 保留；check 的消息只在失败时求值。

## 3～5 分钟练习

把 lowercase 行的期望改为 Success(READY)，运行后恢复。

## 参考答案

应抛 IllegalStateException，消息指向 lowercase 和 ready；恢复后完成三项。普通循环失败后停止，不是三项独立测试报告。
