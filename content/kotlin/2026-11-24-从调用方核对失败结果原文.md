## 用途或适用场景

验证第54课Failure保留inputName的描述。

## 核心概念

使用已有Failure(inputName)构造独立期望；两个空格属于输入内容，文档注释不会让解析器自动trim。

## 最小代码或操作示例

在原同模块、同package新建ContractStatusCheck.kt，沿已学普通函数而不加main：
```kotlin
fun checkFailureContract() {
    val expected = StatusParseResult.Failure(" READY ")
    val actual = parseStatus(" READY ")
    check(actual == expected) { "Failure必须保留原始空格输入" }
    println("失败原文契约检查完成")
}
```
在RunStatusChecks.kt原唯一main中、原testStatusParsing调用之后仅调用checkFailureContract()一次。原九行表、StatusParser及KDoc不改；运行同一入口，分别记录9项与契约演练。

## 3～5 分钟练习

独立期望若写Failure("READY")，应该改解析器去空格来满足吗？

## 参考答案

不应；这与既有精确匹配和原文保留契约冲突。恢复期望为" READY "，保持原九行覆盖。
