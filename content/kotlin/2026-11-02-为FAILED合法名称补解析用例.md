# 第 39 课：为FAILED合法名称补解析用例

- 日期：2026-11-02
- 课程序号：第 39 课
- 知识点：合法状态清单与固定数量同步

## 用途或适用场景

补齐原状态枚举中FAILED的合法名称输入。

## 核心概念

FAILED已属于原枚举，补一行合法输入即可覆盖。仍按精确名称解析，不接受小写或添加新枚举；调用方数量应与清单同步。

## 最小代码或操作示例

沿第37课数量断言和第38课READY新增行，在checkStatusParsing的cases保留原七行并追加：

```kotlin
StatusParseCase("failed", "FAILED", StatusParseResult.Success(LessonStatus.FAILED)),
```

放在listOf最后一项时按原逗号格式衔接；原数据模型与parseStatus不变。main把固定数量检查改成：

```kotlin
check(checkedCount == 8) {
    "完成数量不符：期望8，实际${checkedCount}"
}
```

return cases.size仍位于全部逐行check之后，函数仍只调用一次。

## 3～5 分钟练习

八项数量正确，但把return放在首轮循环内部，可以判全部输入通过吗？

## 参考答案

不可以。数量返回不证明逐行执行；保留完整循环和其后的return，失败名称仍对应具体输入。
