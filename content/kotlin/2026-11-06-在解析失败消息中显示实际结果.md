# 第 43 课：在解析失败消息中显示实际结果

- 日期：2026-11-06
- 课程序号：第 43 课
- 知识点：单次求值与具名诊断

## 用途或适用场景

让第42课记录可直接取得同轮解析返回。

## 核心概念

把parseStatus结果先保存，再同时用于比较和消息；失败时显示输入、期望、实际。只求值一次，避免诊断再调用被测函数。

## 最小代码或操作示例

沿第41课具名失败和第42课三项来源，在checkStatusParsing原for循环内只替换逐行check部分：
```kotlin
val actual = parseStatus(case.inputName)
check(actual == case.expected) {
    "${case.name}: input=[${case.inputName}], " +
        "expected=${case.expected}, actual=$actual"
}
```
沿原StatusParseCase字段、九行表、return cases.size及main固定9；不改parseStatus、大小写或空格语义。可在副本重复第41课错误期望反例，读实际消息后恢复。

## 3～5 分钟练习

为什么不在消息里再调用parseStatus(case.inputName)？

## 参考答案

实际栏应来自本次用于比较的返回值；保存actual可避免重复执行及未来带副作用时的歧义。
