# 第 36 课：让解析检查函数返回完成数量

- 日期：2026-10-28
- 课程序号：第 36 课
- 知识点：显式Int返回类型与调用方输出

## 用途或适用场景

显式Int返回类型与调用方输出，用于继续完成本路线原示例的下一步。

## 核心概念

块函数返回Int要在签名中声明，并在所有检查完成后return cases.size。失败仍由check抛出，调用方不能得到一个伪造的完成数量。

## 最小代码或操作示例

保留原枚举、parseStatus与StatusParseCase，用下列完整函数替换原checkStatusParsing：

```kotlin
fun checkStatusParsing(): Int {
    val cases = listOf(
        StatusParseCase("done", "DONE", StatusParseResult.Success(LessonStatus.DONE)),
        StatusParseCase("lowercase", "ready", StatusParseResult.Failure("ready")),
        StatusParseCase("empty", "", StatusParseResult.Failure("")),
        StatusParseCase("leading-space", " DONE", StatusParseResult.Failure(" DONE")),
        StatusParseCase("trailing-space", "DONE ", StatusParseResult.Failure("DONE ")),
        StatusParseCase("lowercase-and-spaces", " done ", StatusParseResult.Failure(" done "))
    )
    for (case in cases) {
        check(parseStatus(case.inputName) == case.expected) {
            "解析检查失败：${case.name}，输入=[${case.inputName}]"
        }
    }
    return cases.size
}
```

原main的单独调用改为以下两行，不再在检查函数内部println：

```kotlin
val checkedCount = checkStatusParsing()
println("${checkedCount}项解析检查完成")
```

return在循环之后，仍不trim或吞check异常。

## 3～5 分钟练习

如果return放在for循环的第一轮内，会把什么错误隐藏起来？

## 参考答案

后五行未执行，返回值也不能代表完成六项；return应在循环之后。故意写错第六行时，应抛错且main不显示完成。
