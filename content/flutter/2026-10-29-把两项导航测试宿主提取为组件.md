# 第 38 课：把两项导航测试宿主提取为组件

- 日期：2026-10-29
- 课程序号：第 38 课
- 知识点：StatelessWidget接收结果回调

## 用途或适用场景

把两项导航测试宿主提取为组件，用于在已有示例中验证StatelessWidget接收结果回调。

## 核心概念

测试宿主只提供可push的首页，并把Future结果传给回调。每项测试仍拥有自己的savedTitle/returned，避免把测试观察放到共享全局变量。

## 最小代码或操作示例

在第36～37课测试文件的main之外定义，沿material导入及原LessonTitleEditor：

```dart
class TitleEditorTestHost extends StatelessWidget {
  const TitleEditorTestHost({super.key, required this.onResult});
  final ValueChanged<String?> onResult;

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Builder(builder: (context) => Scaffold(
        body: ElevatedButton(
          onPressed: () async {
            final title = await Navigator.push<String>(context,
              MaterialPageRoute<String>(
                builder: (_) => const LessonTitleEditor()));
            onResult(title);
          },
          child: const Text('编辑标题'),
        ),
      )),
    );
  }
}
```

两项测试只替换pumpWidget宿主部分，分别保留本项局部变量；取消测试使用：

```dart
await tester.pumpWidget(TitleEditorTestHost(onResult: (title) {
  savedTitle = title;
  returned = true;
}));
```

有效标题测试回调仅给原savedTitle赋值。其余输入、pop、pumpAndSettle和最终断言全部保留；Builder取得MaterialApp内部的context。

## 3～5 分钟练习

若将savedTitle移到文件全局供两项共用，会增加什么问题？

## 参考答案

上一项结果可能污染下一项起点；保留测试局部变量。组件只复用导航流程，不保存业务结果或改变取消语义。
