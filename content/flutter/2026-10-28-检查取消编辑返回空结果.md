# 第 37 课：检查取消编辑返回空结果

- 日期：2026-10-28
- 课程序号：第 37 课
- 知识点：未提交退出的Navigator结果

## 用途或适用场景

未提交退出的Navigator结果，用于继续完成本路线原示例的下一步。

## 核心概念

编辑器被pop而未传入结果时，push<String>的Future完成为null。测试先记录回调确已返回，再断言null，避免把“仍未返回”的初值误当取消成功。

## 最小代码或操作示例

在第36课测试旁新增，沿用相同导航宿主；编辑器没有AppBar，不调用寻找返回按钮的pageBack：

```dart
testWidgets('取消编辑返回null', (tester) async {
  String? savedTitle;
  bool returned = false;
  await tester.pumpWidget(MaterialApp(
    home: Builder(builder: (context) => Scaffold(
      body: ElevatedButton(
        onPressed: () async {
          savedTitle = await Navigator.push<String>(context,
            MaterialPageRoute<String>(
              builder: (_) => const LessonTitleEditor()));
          returned = true;
        },
        child: const Text('编辑标题'),
      ),
    )),
  ));
  await tester.tap(find.text('编辑标题'));
  await tester.pumpAndSettle();
  await tester.enterText(find.byType(TextField), '未提交标题');
  Navigator.of(tester.element(find.byType(LessonTitleEditor))).pop();
  await tester.pumpAndSettle();
  expect(returned, isTrue);
  expect(savedTitle, isNull);
  expect(find.byType(LessonTitleEditor), findsNothing);
  expect(find.text('编辑标题'), findsOneWidget);
});
```

这里直接调用原Navigator的取消返回，未模拟系统返回手势或持久化。

## 3～5 分钟练习

只检查savedTitle为null、删去returned和页面断言，会漏掉什么？

## 参考答案

可能漏掉路由根本未退出；null也是初始值。应同时证明Future已完成及编辑器消失。
