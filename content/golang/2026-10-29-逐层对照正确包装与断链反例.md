# 第 37 课：逐层对照正确包装与断链反例

- 日期：2026-10-29
- 课程序号：第 37 课
- 知识点：errors.Unwrap只取一层

## 用途或适用场景

逐层对照正确包装与断链反例，用于在已有示例中验证errors.Unwrap只取一层。

## 核心概念

errors.Unwrap只调用Unwrap() error取得一层，不等于errors.Is的整链查找。对两条文字相同的链逐层读取，可以看见身份从哪里丢失。

## 最小代码或操作示例

沿第35课定向运行与第36课独立反例，在原_test.go新增，保留七行原表：

```go
func TestUnwrapOneLevel(t *testing.T) {
    root := errors.New("disk")
    goodInner := fmt.Errorf("save: %w", root)
    good := fmt.Errorf("submit: %w", goodInner)
    brokenInner := fmt.Errorf("save: %v", root)
    broken := fmt.Errorf("submit: %w", brokenInner)
    if errors.Unwrap(good) != goodInner || errors.Unwrap(goodInner) != root {
        t.Fatal("正确包装应逐层到达同一根错误")
    }
    if errors.Unwrap(broken) != brokenInner || errors.Unwrap(brokenInner) != nil {
        t.Fatal("普通格式化产生的内层没有解包结果")
    }
    if good.Error() != broken.Error() {
        t.Fatal("本例两条错误文字应相同")
    }
}
```

沿errors、fmt、testing导入，在原包运行go test -run '^TestUnwrapOneLevel$' -v，再go test -v。只讨论单错误包装，不推广到Unwrap() []error。

## 3～5 分钟练习

Unwrap(broken)非nil，是否意味着errors.Is(broken, root)会为true？

## 参考答案

不会；它只返回brokenInner，下一层已经为nil。原独立反例继续检查根身份不可达。
