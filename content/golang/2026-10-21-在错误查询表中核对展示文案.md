# 第 31 课：在错误查询表中核对展示文案

- 日期：2026-10-21
- 课程序号：第 31 课
- 知识点：同一用例覆盖 message 的独立契约

## 用途或适用场景

同时发现根身份正确但用户提示映射错误的问题。

## 核心概念

错误类型、根身份和展示文案分别断言。文案期望写为固定字符串，不用 message 自己计算预期；文案断言位于类型缺失的提前 return 之前。

## 最小代码或操作示例

在第 30 课同一个 TestMinutesTypeCases 表格结构中，在 wantRoot error 字段后追加 wantMessage string，并将表行替换为：

```go
{"wrapped", fmt.Errorf("save: %w", &MinutesError{Minutes: -3, Err: errMinutes}), true, -3, errMinutes, "请输入正数分钟"},
{"root-only", fmt.Errorf("save: %w", errMinutes), false, 0, errMinutes, "请输入正数分钟"},
{"too-long", fmt.Errorf("save: %w", &MinutesError{Minutes: 80, Err: errTooLong}), true, 80, errTooLong, "最多 60 分钟"},
```

在 t.Run 内原 Is 检查后、AsType 检查前加入：

```go
if got := message(tc.err); got != tc.wantMessage {
    t.Fatalf("message=%q, want=%q", got, tc.wantMessage)
}
```

其余 Minutes/is 命中断言与原 message 不改，使用 Go 1.26+ 运行 go test lesson.go lesson_test.go。

## 3～5 分钟练习

把 root-only 的期望文案临时改成上限提示，运行后恢复。

## 参考答案

该子测试必须失败，证明未命中 MinutesError 时也执行文案检查。三项正确文案分别为正数、正数、上限；文案不是错误身份的判断依据。
