# 第 26 课：让错误包装携带失败分钟数

- 日期：2026-10-13
- 课程序号：第 26 课
- 知识点：实现 `Error()` / `Unwrap()` 的错误包装类型

## 用途或适用场景

在保留根错误身份的同时，给已有错误链增加具体失败分钟数。

## 核心概念

`MinutesError` 保存输入分钟数和已有错误。`Error()` 使它满足 error 接口；`Unwrap()` 返回原错误，让上一课的 `errors.Is` 可以继续穿透。这两个方法共同构成一个完整包装类型；本课暂不检索类型字段。

## 最小代码或操作示例

在原 `lesson.go` 的 package/import 后新增类型与方法：

```go
type MinutesError struct {
    Minutes int
    Err error
}

func (e *MinutesError) Error() string {
    return fmt.Sprintf("minutes=%d: %v", e.Minutes, e.Err)
}

func (e *MinutesError) Unwrap() error { return e.Err }
```

保留第 25 课的 `first`，把测试中的第二层包装改为以下代码；`fmt` 与 `errors` 沿用已有导入：

```go
first := fmt.Errorf("validate: %w", errMinutes)
second := &MinutesError{Minutes: -3, Err: first}
if !errors.Is(second, errMinutes) {
    t.Fatal("lost identity")
}
if got := message(second); got != "请输入正数分钟" {
    t.Fatalf("message=%q", got)
}
```

把 `second` 用 `%v` 输出可观察上下文，继续运行原测试命令。

## 3～5 分钟练习

将包装类型的 `Minutes` 改为 80、根错误改为已有 `errTooLong`；核对错误身份与提示值。

## 参考答案

`errors.Is(second, errTooLong)` 为 true，`message(second)` 仍为“最多 60 分钟”；错误文本包含 `minutes=80`。分钟数字段与提示函数各有用途。

## 与上一课的联系
