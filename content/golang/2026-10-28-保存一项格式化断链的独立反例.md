# 第 36 课：保存一项格式化断链的独立反例

- 日期：2026-10-28
- 课程序号：第 36 课
- 知识点：相同错误文字不代表同一错误身份

## 用途或适用场景

相同错误文字不代表同一错误身份，用于继续完成本路线原示例的下一步。

## 核心概念

%v保留可读文字却不提供Unwrap链。把这个反例作为应通过的独立测试，长期检查errors.Is不能穿过已丢失的包装，而不是把故意失败的改动留在原七行里。

## 最小代码或操作示例

保留第34～35课已恢复%w的七行，在原_test.go内新增；沿用errors、fmt、testing导入：

```go
func TestBrokenWrappingLosesIdentity(t *testing.T) {
    unexpected := errors.New("disk")
    broken := fmt.Errorf("submit: %w", fmt.Errorf("save: %v", unexpected))
    if errors.Is(broken, unexpected) {
        t.Fatal("内层普通格式化不应保留根身份")
    }
    if broken.Error() != "submit: save: disk" {
        t.Fatalf("错误文字不符：%q", broken.Error())
    }
}
```

沿原Go1.26+项目运行go test -run '^TestBrokenWrappingLosesIdentity$' -v，再运行go test -v。原七行继续证明正确%w链可被查到，新方法证明断链时查不到。

## 3～5 分钟练习

把本反例内层%v改成%w但不改断言，哪项应失败？然后恢复反例。

## 参考答案

errors.Is会找到同一unexpected，第一项应失败；错误文字可能相同，不能仅比较文字判断链是否存在。
