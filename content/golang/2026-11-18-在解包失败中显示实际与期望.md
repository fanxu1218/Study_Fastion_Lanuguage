# 第 51 课：在解包失败中显示实际与期望

- 日期：2026-11-18
- 课程序号：第 51 课
- 知识点：失败消息并列两个nil状态

## 用途或适用场景

让第50课带名称的诊断说明原七行表哪一侧缺解包结果。

## 核心概念

身份比较仍用got != want；nil状态只辅助解释，两个非nil也可能不是同一个错误对象。

## 最小代码或操作示例

用以下函数替换原_test.go的checkUnwrap，原调用与七行表不变：
```go
func checkUnwrap(t *testing.T, name string, err error, want error) {
    t.Helper()
    got := errors.Unwrap(err)
    if got != want {
        t.Fatalf("单层解包不符：%s；actualNil=%t，wantNil=%t",
            name, got == nil, want == nil)
    }
}
```
先运行原全部测试；个人副本仅把good行inner临时改为nil，再用原go test -run '^TestWrappingComparison/good$' -v。应非零、含good、actualNil=false及wantNil=true，文件/行仍指向helper调用。恢复goodInner，再运行原全部测试。

## 3～5 分钟练习

actualNil和wantNil都是false，能推断两个解包身份相同吗？

## 参考答案

不能；非nil只是存在，最终身份仍由got != want判断，不改成比较文字或nil状态。
