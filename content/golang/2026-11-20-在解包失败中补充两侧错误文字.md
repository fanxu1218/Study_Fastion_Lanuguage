# 第 53 课：在解包失败中补充两侧错误文字

- 日期：2026-11-20
- 课程序号：第 53 课
- 知识点：fmt的%v辅助身份诊断

## 用途或适用场景

解释第52课两个非nil对象为何仍会失败，同时看见它们的展示文字。

## 核心概念

%v按默认格式输出错误值，nil显示为<nil>；文字只供阅读，最终身份仍由got != want判断。

## 最小代码或操作示例

只替换原_test.go的checkUnwrap，保留原七行表与所有调用：
```go
func checkUnwrap(t *testing.T, name string, err error, want error) {
    t.Helper()
    got := errors.Unwrap(err)
    if got != want {
        t.Fatalf("单层解包不符：%s；actualNil=%t，wantNil=%t；actual=%v，want=%v",
            name, got == nil, want == nil, got, want)
    }
}
```

## 3～5 分钟练习

消息显示actual和want文字完全相同，可把比较改为got.Error() == want.Error()吗？

## 参考答案

不能；同文案不等于同对象，且nil也不能直接调用Error。保留got != want，文字仅作诊断。
