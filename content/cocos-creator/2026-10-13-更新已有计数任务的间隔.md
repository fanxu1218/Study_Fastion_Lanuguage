# 第 25 课：更新已有计数任务的间隔

- 日期：2026-10-13
- 课程序号：第 25 课
- 知识点：再次 schedule 同一 tick 更新 interval

## 用途或适用场景

让仍在启用中的节点 A 调整计数节奏，节点 B 继续使用自己的间隔。

## 核心概念

复用上一课同一 tick 引用。只修改当前实例的 interval，然后以已有下限调用 schedule；调度器更新已有任务的间隔，count 不重置。示例只在组件和节点都已启用时调用。

## 最小代码或操作示例

把方法加入原组件，保留上一课的 onEnable/onDisable：

```ts
public changeInterval(seconds: number): void {
  this.interval = seconds
  this.schedule(this.tick, Math.max(this.interval, 0.1))
}
```

用已学过的 `scheduleOnce` 做一次临时验证：在现有 `start` 中加入 `this.scheduleOnce(() => this.changeInterval(0.5), 3)`，并确保这里没有旧的计数 `schedule`。A 的初始 interval 设为 1；验证后移除这条临时调用。

## 3～5 分钟练习

节点 A、B 初始 interval 都设为 1；只给 A 加上面的三秒后调用。运行约 8 秒，对照日志中两个节点的计数增长速度。

## 参考答案

三秒后的稳定观察段，A 约每 0.5 秒增加一次，B 仍约每 1 秒增加一次；帧调度会有偏差，不要求精确毫秒。A 的 count 连续增加，没有叠加第二份 tick。

## 与上一课的联系

继承第 24 课同引用 schedule 更新而不叠加的语义，沿用 count、tick、interval 和原 onDisable 清理；本课只把新间隔传回现有调度。下一课可独立处理组件禁用期间修改 interval 的调用边界。
