# 第 28 课：用活动控制器观察持续停用期

- 日期：2026-10-16
- 课程序号：第 28 课
- 知识点：调度任务必须属于仍活动的组件

## 用途或适用场景

让节点 A 停用两秒后恢复，观察停用窗口内是否停止计数。

## 核心概念

被停用节点无法承担自己的延迟恢复任务。把恢复 scheduleOnce 放在场景中独立且持续活动的控制节点上；A仍由原 onDisable/onEnable取消/恢复，不新增调度状态。

## 最小代码或操作示例

移除 A.start 中第 27 课的临时四行。新建 SuspendProbe.ts，挂到不在 A 子树中的独立活动节点；在 Inspector 将 target 拖为 A：

```ts
import { _decorator, Component, Node } from 'cc';
const { ccclass, property } = _decorator;

@ccclass('SuspendProbe')
export class SuspendProbe extends Component {
  @property(Node)
  target: Node | null = null;

  start(): void {
    const target = this.target;
    if (target === null) {
      console.error('SuspendProbe: target 未配置');
      return;
    }
    target.active = false;
    console.log('A inactive');
    this.scheduleOnce(() => {
      target.active = true;
      console.log('A active again');
    }, 2);
  }
}
```

A保持已有 interval，B继续1秒；控制器在这两秒中不禁用，测试后移除该探针组件。

## 3～5 分钟练习

观察两条边界日志之间的 A/B tick；恢复后核对 A 的 count 从原值继续。

## 参考答案

持续停用窗口内A不计数，B继续；恢复由A原onEnable注册，count未被探针重置。两秒是目标调度延迟，实际触发受帧调度影响。
