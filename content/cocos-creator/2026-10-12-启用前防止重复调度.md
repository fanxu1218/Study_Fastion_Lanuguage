# 第 24 课：启用前防止重复调度

- 日期：2026-10-12
- 课程序号：第 24 课
- 知识点：复用同一回调引用的调度语义

## 用途或适用场景

确认启用流程复用已有 tick，而不是每次生成新的回调函数。

## 核心概念

官方 schedule 的约定是：当前组件中同一回调已调度时，再次调用只更新 interval，不再增加一个任务。因此不需要用 unschedule 来弥补不存在的同引用重复任务。onDisable 仍负责取消；保留第 15 课的间隔下限。

## 最小代码或操作示例

替换第 23 课的启用片段，`tick` 仍是已有的同一个回调；不要在 `start` 再注册计数：

```ts
protected onEnable(): void {
  const seconds = Math.max(this.interval, 0.1)
  this.schedule(this.tick, seconds)
}
```

要验证 API 语义，可临时在同一 `onEnable` 内连续调用两次 `this.schedule(this.tick, seconds)`；验证后移除第二次调用。不要手动调用生命周期方法。

## 3～5 分钟练习

在节点 A 的启用片段临时加第二次同引用 schedule，运行后比较 A 与原本相同间隔的节点 B 的日志计数，再删除临时行。

## 参考答案

相同间隔下 A 不会因为同引用的第二次调用而按双倍频率计数。创建不同匿名函数会产生不同回调，本课示例不这样做。

## 与上一课的联系

继承第 23 课 onEnable 恢复与第 22 课 onDisable 取消的对称结构；本课只验证同引用不叠加的官方语义。下一课可对同一 tick 再次 schedule，以更新已有任务的间隔。
