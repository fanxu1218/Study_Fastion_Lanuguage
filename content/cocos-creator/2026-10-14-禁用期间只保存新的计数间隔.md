# 第 26 课：禁用期间只保存新的计数间隔

- 日期：2026-10-14
- 课程序号：第 26 课
- 知识点：enabledInHierarchy 调度边界

## 用途或适用场景

禁用组件时修改 interval，等重新启用后再由原 onEnable 注册计数任务。

## 核心概念

enabledInHierarchy 同时考虑组件 enabled 和节点 activeInHierarchy。禁用时只更新 interval；onEnable 按保存的值恢复，仍复用同一个 tick，不用额外调度状态或私有字段。

## 最小代码或操作示例

替换第 25 课 changeInterval，保留原 onEnable/onDisable：

```ts
public changeInterval(seconds: number): void {
  this.interval = seconds
  if (this.enabledInHierarchy) {
    this.schedule(this.tick, Math.max(this.interval, 0.1))
  }
}
```

在已有 start 中可临时使用以下一次性验证；移除上一课的临时调用后再加入，验证后也移除：

```ts
this.enabled = false
this.changeInterval(0.5)
this.enabled = true
```

生命周期由引擎触发，不手动调用 onEnable/onDisable。

## 3～5 分钟练习

只对节点 A 执行上述验证，节点 B 保持 interval=1；观察重新启用后的日志计数，检查 count 没有重置。

## 参考答案

A 重新启用后使用 0.5 秒，B 仍用 1 秒；禁用阶段 changeInterval 不执行 schedule。日志间隔会受帧影响，真实引擎结果需实际运行。
