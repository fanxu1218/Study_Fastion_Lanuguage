# 第 30 课：按图片路径核对工程附件来源

- 日期：2026-10-21
- 课程序号：第 30 课
- 知识点：Images 根路径与附件 Path 的查找规则

## 用途或适用场景

补齐预览共同来源工程所依赖的图片清单。

## 核心概念

Images 指定根目录，附件若设置 Path 则优先用 Path，否则用附件名称查找图片。设置 JSON 和 .spine 都不能替代这些源图；文件名大小写也影响部分系统。

## 最小代码或操作示例

打开第 29 课已确认的同一 .spine，不改 hero-winter 的搭配和帧：

```text
1. 在树中选 Images，记录当前路径是相对工程还是绝对路径。
2. 选一个当前使用的区域附件，记录其 Name 与是否设置 Path。
3. 按“Images根目录 + Path（若有）或Name + 图片扩展名”核对实际文件。
4. 在原清单追加：附件 | 根路径 | 有效查找名 | 实际源图 | 是否可读取。
5. 对缺失项保留事实，不导出新预览或用同名假图替代。
```

例如根为 ./images/、名称 head 且无 Path 时，核对 images/head.png 等实际支持文件；例名只解释规则，清单使用原工程实际名称。

## 3～5 分钟练习

附件 Name=head、Path=skins/winter/head，根为 ./images/，应优先核对哪里？

## 参考答案

核对 Images 根下 skins/winter/head 的 PNG/JPG/JPEG 实际文件，不能只查 head.png。相对路径以保存的 .spine 位置为基准；无访问证据仍记待确认。
