# 第 58 课：给契约失败消息补充两个实参

- 日期：2026-11-27
- 课程序号：第 58 课
- 知识点：调用方诊断保留参数边界

## 用途或适用场景

在第57课返回值输出旁，为实际进入失败分支的调用保留输入证据。

## 核心概念

参数原文与boolean返回值属于不同证据。消息只由调用方构造，不改变textsMatch的equals契约或原if(actual)判定。

## 最小代码或操作示例

在ContractTextCheck.main原if(actual)中，仅替换throw：
```java
throw new AssertionError(
    "空格契约应返回false：expectedText=[" + expectedText
    + "]；actualText=[" + actualText + "]；actual=" + actual);
```
正常仍沿expectedText="Java"、actualText=" Java "及原输出。用javac --release 17 -d classes-lesson58编译原五文件（输出目录未占用），分别启动ContractTextCheck和RunTextChecks；有package使用完整类名。

## 3～5 分钟练习

个人副本只将actualText临时改为"Java"，运行独立契约，观察消息后恢复再回归。

## 参考答案

两侧均为Java、actual=true，应抛AssertionError且非零；消息中的expectedText是textsMatch形参角色，不是布尔期望。恢复带空格输入后返回false并正常结束，原六项另外执行。

## 与上一课的联系

继承第56课实参角色与第57课返回值展示；本课只补调用方失败诊断。下一课可在诊断中把空格显示得更清楚，保留原精确比较。
