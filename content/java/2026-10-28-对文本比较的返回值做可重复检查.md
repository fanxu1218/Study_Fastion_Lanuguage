# 第 36 课：对文本比较的返回值做可重复检查

- 日期：2026-10-28
- 课程序号：第 36 课
- 知识点：显式失败与固定布尔期望

## 用途或适用场景

显式失败与固定布尔期望，用于继续完成本路线原示例的下一步。

## 核心概念

检查方法比较实际boolean和独立期望，不用输出文字代替结果。显式抛AssertionError会让失败可见；文件I/O仍留在原main流程，练习不写文件。

## 最小代码或操作示例

保留第35课textsMatch，在同一类内、main外新增：

```java
static void checkTextsMatch() {
    if (!textsMatch("课程", "课程")) {
        throw new AssertionError("相同文本应匹配");
    }
    if (textsMatch("课程", "课程\n")) {
        throw new AssertionError("额外换行应不匹配");
    }
    if (!textsMatch("", "")) {
        throw new AssertionError("两个空文本应匹配");
    }
}
```

在main最前调用checkTextsMatch();再执行原逻辑；需要只练内存时，在独立副本main中仅调用本方法。这里使用if/throw，不依赖java -ea；沿非null输入前提。

## 3～5 分钟练习

把第二项条件错误改成!textsMatch，为什么即使比较实现正确也会失败？

## 参考答案

预期是不匹配，即false；错误取反会触发失败。先恢复独立期望，不应改textsMatch迎合错误断言。字符串内使用反斜杠n。
