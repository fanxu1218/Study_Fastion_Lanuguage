# 第 37 课：给文本比较检查增加用例名称

- 日期：2026-10-29
- 课程序号：第 37 课
- 知识点：具名实参与失败定位

## 用途或适用场景

给文本比较检查增加用例名称，用于在已有示例中验证具名实参与失败定位。

## 核心概念

让检查方法接收名称、两份文本及独立boolean期望，失败时报告具体用例。textsMatch仍只负责比较，不读取文件或修改文本。

## 最小代码或操作示例

保留第35课textsMatch，在同一类、main外增加辅助方法，并替换第36课检查入口：

```java
static void checkTextCase(String name, String expectedText,
                          String actualText, boolean expectedMatch) {
    if (textsMatch(expectedText, actualText) != expectedMatch) {
        throw new AssertionError("比较检查失败：" + name);
    }
}

static void checkTextsMatch() {
    checkTextCase("same", "课程", "课程", true);
    checkTextCase("extra-newline", "课程", "课程\n", false);
    checkTextCase("both-empty", "", "", true);
}
```

main保留一次checkTextsMatch()，纯内存副本只运行它。保留非null前提；字符串内的反斜杠n表示换行，不在引号中另起一行。

## 3～5 分钟练习

把extra-newline的期望错填true，应由哪条提示定位？

## 参考答案

应抛AssertionError并包含extra-newline；恢复false后全部通过。仍不能据此声称文件读写成功。
