# 第 75 课：为共享挂起任务传入延迟参数

- 日期：2026-10-23
- 课程序号：第 75 课
- 知识点：挂起函数参数与原测试调度的衔接

## 用途或适用场景

为共享挂起任务传入延迟参数。

## 核心概念

参数改变任务等待时长，不改变调用方Job、取消传播或finally同步清理。继续保留first=100与second大于100的先后条件。

## 最小代码或操作示例

将第74课runSecond替换为下列签名与函数体，仍放在原测试类内：

```kotlin
private suspend fun runSecond(
    delayMillis: Long,
    completed: MutableList<String>,
    onCleanup: (String) -> Unit
) {
    try {
        delay(delayMillis)
        completed += "second"
    } finally {
        onCleanup("second")
    }
}
```

两项测试的调用都改为：

```kotlin
val second = launch { runSecond(200L, completed, onCleanup) }
```

导入、opt-in、runCurrent、advanceTimeBy(100)、取消/正常断言不变。

## 3～5 分钟练习

把两处200L都改为300L，运行同一对测试，记录清理名称与completed。

## 参考答案

取消路径completed仅first，正常路径含first/second；cleanupNames最终均仅second一次。若传入50L，原100时间点前提已改变，不能保留旧中间断言并期待通过。

## 与上一课的联系
