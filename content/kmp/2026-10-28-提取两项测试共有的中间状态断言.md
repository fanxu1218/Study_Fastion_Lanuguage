# 第 78 课：提取两项测试共有的中间状态断言

- 日期：2026-10-28
- 课程序号：第 78 课
- 知识点：只提取观察而保留调度顺序

## 用途或适用场景

只提取观察而保留调度顺序，用于继续完成本路线原示例的下一步。

## 核心概念

正常与取消用例在100毫秒时具有相同前置观察。辅助方法只读取列表和Job，不推进时间、不取消任务；分支动作仍留在各测试内。

## 最小代码或操作示例

在第76～77课同一commonTest类内新增，沿用assertEquals/assertTrue并补import kotlinx.coroutines.Job：

```kotlin
private fun assertSecondPending(
    completed: List<String>,
    cleanupNames: List<String>,
    second: Job
) {
    assertEquals(listOf("first"), completed)
    assertEquals(emptyList<String>(), cleanupNames)
    assertTrue(!second.isCompleted)
}
```

两项300L测试在advanceTimeBy(100)之后仍调用runCurrent()，然后用assertSecondPending(completed, cleanupNames, second)替换中间状态的三项断言。取消用例原先没有isCompleted断言，本次由同一辅助方法补齐。各自的join/cancelAndJoin及最终断言完整保留；原200L用例不改。

## 3～5 分钟练习

若把cancelAndJoin放入辅助方法，正常路径还能检查同一任务正常完成吗？

## 参考答案

不能；这会改变测试动作。辅助方法只检查状态，两项300L用例仍分别应得到first/second与仅first，清理都一次。
