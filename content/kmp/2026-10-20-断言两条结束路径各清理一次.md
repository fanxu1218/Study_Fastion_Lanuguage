# 第 72 课：断言两条结束路径各清理一次

- 日期：2026-10-20
- 课程序号：第 72 课
- 知识点：用次数断言同步清理

## 用途或适用场景

在既有正常/取消用例中发现重复清理。

## 核心概念

布尔值只能证明清理曾执行；计数还能发现执行两次。计数只是测试观察量，不参与业务状态，两条测试仍各自创建任务。

## 最小代码或操作示例

在第 70、71 课两个测试中分别执行同样的局部替换，保留其余调度和业务断言：

```text
var cleaned = false          → var cleanupCount = 0
finally { cleaned = true }   → finally { cleanupCount += 1 }
assertTrue(!cleaned)          → assertEquals(0, cleanupCount)
assertTrue(cleaned)           → assertEquals(1, cleanupCount)
```

正常路径保留 second.join()，取消路径保留 second.cancelAndJoin()。两项测试末尾都追加：

```kotlin
advanceUntilIdle()
assertEquals(1, cleanupCount)
```

沿用 commonTest 导入、runTest 与 ExperimentalCoroutinesApi opt-in，不再保留 cleaned 变量或对应断言。

## 3～5 分钟练习

在某一练习副本 finally 中临时把计数增加两次，运行测试后恢复。

## 参考答案

原代码两条路径最终均为1；增加两次使相应测试失败。取消路径 completed 仍只含 first，正常路径为 first/second，清理次数不等于业务完成次数。
