# 第 73 课：让同步清理回调记录任务名称

- 日期：2026-10-21
- 课程序号：第 73 课
- 知识点：带参数的清理函数类型

## 用途或适用场景

在原两条结束路径中同时核对清理次数和对象名称。

## 核心概念

(String) -> Unit 表示接收任务名且无业务返回值的同步回调。回调只记录测试观察，不挂起、不捕获取消异常；second 的 finally 仍是唯一调用点。

## 最小代码或操作示例

在第 72 课的取消/正常两项测试中分别作以下替换，保留 first、completed、调度顺序和任务状态断言：

```kotlin
// 替换 cleanupCount 声明；两项测试各自独立声明。
val cleanupNames = mutableListOf<String>()
val onCleanup: (String) -> Unit = { name -> cleanupNames += name }
```

将 second 的 finally 内容替换为 onCleanup("second")。将原清理次数断言逐一替换为：

```kotlin
// 在结束之前，替换原 assertEquals(0, cleanupCount)
assertEquals(emptyList<String>(), cleanupNames)
// 在 cancelAndJoin()/join() 之后，以及 advanceUntilIdle() 之后
assertEquals(listOf("second"), cleanupNames)
```

不保留旧 cleanupCount；commonTest 导入、runTest 与 ExperimentalCoroutinesApi opt-in 沿用。

## 3～5 分钟练习

在一个测试副本中把 finally 参数改成 first，运行后恢复 second。

## 参考答案

名称断言失败；原正确代码的两条路径均只记录一次 second。取消路径 completed 仍只有 first，正常路径为 first/second；清理记录不冒充业务完成。
