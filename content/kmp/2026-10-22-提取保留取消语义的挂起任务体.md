# 第 74 课：提取保留取消语义的挂起任务体

- 日期：2026-10-22
- 课程序号：第 74 课
- 知识点：suspend 函数承载已有 try/finally

## 用途或适用场景

让正常和取消测试调用同一个 second 任务体。

## 核心概念

suspend 允许函数调用 delay，函数本身不启动新协程。launch 仍由测试持有，取消继续沿原 Job 传播；同步清理回调仍只在 finally 调用一次。

## 最小代码或操作示例

沿第 73 课测试，在同一测试类内、两个测试方法外新增（delay 导入沿用）：

```kotlin
private suspend fun runSecond(
    completed: MutableList<String>,
    onCleanup: (String) -> Unit
) {
    try {
        delay(200)
        completed += "second"
    } finally {
        onCleanup("second")
    }
}
```

在取消和正常两项测试里，各把原 second 的 launch 块替换为：

```kotlin
val second = launch { runSecond(completed, onCleanup) }
```

保留 first 的 delay(100)、runCurrent/advanceTimeBy、cancelAndJoin 或 join、cleanupNames 和全部断言；不添加新作用域、异常捕获或真实睡眠。

## 3～5 分钟练习

在一个副本将函数内 delay 改成300，同时运行两条原测试，再恢复200。

## 参考答案

两条最终清理都为 listOf("second")；取消路径 completed 只有 first，正常路径为 first/second。任务体抽取不改变 Job 归属或完成条件。
