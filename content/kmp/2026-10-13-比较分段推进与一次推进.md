# 第 68 课：比较分段推进与一次推进

- 日期：2026-10-13
- 课程序号：第 68 课
- 知识点：同一任务的推进策略对照

## 用途或适用场景

确认测试拆成两个 50 毫秒步骤后，仍得到上一课的完成集合与 100 毫秒耗时。

## 核心概念

只比较推进策略，任务名、两次 delay(100) 与 completed 不变。第二轮从新的 startedAt 开始，比较经过时间，不能把绝对 currentTime 错当成本轮耗时。

## 最小代码或操作示例

```kotlin
import kotlin.test.Test
import kotlin.test.assertEquals
import kotlinx.coroutines.ExperimentalCoroutinesApi
import kotlinx.coroutines.delay
import kotlinx.coroutines.launch
import kotlinx.coroutines.test.advanceTimeBy
import kotlinx.coroutines.test.advanceUntilIdle
import kotlinx.coroutines.test.currentTime
import kotlinx.coroutines.test.runCurrent
import kotlinx.coroutines.test.runTest

@OptIn(ExperimentalCoroutinesApi::class)
@Test
fun comparesAdvanceStrategies() = runTest {
    val completed = mutableListOf<String>()
    fun launchTasks() {
        launch { delay(100); completed += "first" }
        launch { delay(100); completed += "second" }
    }
    launchTasks()
    advanceUntilIdle()
    val expected = completed.toSet()
    val expectedDuration = currentTime

    completed.clear()
    val startedAt = currentTime
    launchTasks()
    runCurrent() // 让第二轮任务从 startedAt 开始计时
    advanceTimeBy(50)
    advanceTimeBy(50)
    runCurrent() // 执行恰好落在 100 毫秒边界上的任务
    assertEquals(expected, completed.toSet())
    assertEquals(expectedDuration, currentTime - startedAt)
}
```

## 3～5 分钟练习

把分段推进改成 25、75；保留边界 runCurrent，运行测试。

## 参考答案

集合仍为 first、second；两轮经过时间均为 100L。删除最后的 runCurrent 时，边界任务尚未执行，集合断言失败。
