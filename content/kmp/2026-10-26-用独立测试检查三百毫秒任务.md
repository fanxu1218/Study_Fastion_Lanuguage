# 第 76 课：用独立测试检查三百毫秒任务

- 日期：2026-10-26

- 知识点：参数化任务的独立正常路径用例

## 用途或适用场景

参数化任务的独立正常路径用例，继续使用本路线的原练习。

## 核心概念

每个runTest重新建立完成列表和清理观察量。改变延迟输入时保留100毫秒中间点，仍检查second没有提前完成及最终只清理一次。

## 最小代码或操作示例

保留原200L正常/取消两项测试及第75课runSecond，在同一测试类新增。沿用原@Test、opt-in及协程测试导入：

```kotlin
@Test
fun secondCompletesAfter300Millis() = runTest {
    val completed = mutableListOf<String>()
    val cleanupNames = mutableListOf<String>()
    val onCleanup: (String) -> Unit = { name -> cleanupNames += name }
    val first = launch { delay(100); completed += "first" }
    val second = launch { runSecond(300L, completed, onCleanup) }
    runCurrent()
    advanceTimeBy(100)
    runCurrent()
    assertEquals(listOf("first"), completed)
    assertEquals(emptyList<String>(), cleanupNames)
    assertTrue(!second.isCompleted)
    first.join()
    second.join()
    assertEquals(listOf("first", "second"), completed)
    assertEquals(listOf("second"), cleanupNames)
    advanceUntilIdle()
    assertEquals(listOf("second"), cleanupNames)
}
```

没有真实sleep，也不在同一测试中复用上一轮Job。

## 3～5 分钟练习

只运行新方法，再运行原测试类，比较清理名称；为什么不能复用原测试的completed？

## 参考答案

各正常路径最终均为first/second，清理仅second一次；复用可变列表会混入上一轮结果，失去独立起点。原取消路径仍仅first。
