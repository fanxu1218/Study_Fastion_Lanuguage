# 第 71 课：对照正常结束时的同步清理

- 日期：2026-10-16
- 课程序号：第 71 课
- 知识点：Job.join 与正常完成的 finally

## 用途或适用场景

在上一课取消测试旁增加正常完成对照，区分清理完成与取消状态。

## 核心概念

finally 在正常结束时也执行。join 只等待任务结束，不发出取消请求；本课仍只做同步清理。保留上一课取消用例，两个用例的 completed 各自独立。

## 最小代码或操作示例

在原 commonTest 类内追加测试，沿用第 69～70 课 import 和依赖：

```kotlin
@OptIn(ExperimentalCoroutinesApi::class)
@Test
fun normalCompletionRunsCleanup() = runTest {
    val completed = mutableListOf<String>()
    var cleaned = false
    launch { delay(100); completed += "first" }
    val second = launch {
        try {
            delay(200)
            completed += "second"
        } finally {
            cleaned = true
        }
    }
    runCurrent()
    advanceTimeBy(100)
    runCurrent()
    assertEquals(listOf("first"), completed)
    assertTrue(!cleaned)
    second.join()
    assertTrue(!second.isCancelled)
    assertTrue(cleaned)
    assertEquals(listOf("first", "second"), completed)
}
```

runTest 在等待 join 时继续调度同一测试调度器的任务，不依赖真实睡眠。

## 3～5 分钟练习

分别运行取消和正常结束用例，比较 cleaned、isCancelled 与 completed；将正常用例第二项延迟改为 300 再运行。

## 参考答案

两条路径 cleaned 都为 true；取消路径只含 first 且 isCancelled=true，正常路径含 first/second 且 isCancelled=false。延长正常延迟不改变最终契约。

## 与上一课的联系

继承第 69 课 first/second/completed 和第 70 课 finally/cleaned；本课只用 join 加入正常结束对照。下一课可检查两条路径的清理是否都只执行一次。
