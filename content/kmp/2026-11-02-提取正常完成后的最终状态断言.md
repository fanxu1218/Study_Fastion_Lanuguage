# 第 81 课：提取正常完成后的最终状态断言

- 日期：2026-11-02
- 课程序号：第 81 课
- 知识点：正常与取消终态独立检查

## 用途或适用场景

整理正常完成断言，同时保留取消路径与虚拟时间顺序。

## 核心概念

正常完成和取消具有不同完成列表。共享的是只读观察方式，不能拿取消辅助方法替正常路径，也不能把join藏进断言。

## 最小代码或操作示例

沿第79课稳定消息和第80课取消辅助方法，在同一commonTest类新增；沿原Job及kotlin.test导入：

```kotlin
private fun assertSecondCompleted(
    completed: List<String>,
    cleanupNames: List<String>,
    second: Job
) {
    assertTrue(second.isCompleted, "second应已结束")
    assertTrue(!second.isCancelled, "second应正常完成")
    assertEquals(listOf("first", "second"), completed, "正常完成顺序")
    assertEquals(listOf("second"), cleanupNames, "second仅清理一次")
}
```

只在第76课secondCompletesAfter300Millis原first.join()、second.join()之后，以assertSecondCompleted(completed, cleanupNames, second)替换两条最终列表断言；中间assertSecondPending、advanceUntilIdle()后清理断言、原200L及取消测试保留。沿ExperimentalCoroutinesApi opt-in和表达式runTest返回。

## 3～5 分钟练习

若先调用新断言再second.join()，是否仍是同一观察点？

## 参考答案

不是；可能在second尚未结束时检查。join留在测试动作中，正常/取消分别调用自己的终态检查。
