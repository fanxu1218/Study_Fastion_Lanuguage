# 第 77 课：为三百毫秒任务增加取消用例

- 日期：2026-10-27
- 课程序号：第 77 课
- 知识点：相同延迟下正常与取消的成对检查

## 用途或适用场景

为三百毫秒任务增加取消用例，让本次练习的结果可以按同一条件复查。

## 核心概念

正常路径与取消路径使用同一runSecond，区别只在100毫秒后是否取消second。cancelAndJoin返回后可以检查同步finally已结束，取消不应写入正常完成列表。

## 最小代码或操作示例

保留第75课参数化runSecond和第76课正常测试。在同一commonTest类新增，沿用原导入与ExperimentalCoroutinesApi opt-in：

```kotlin
@Test
fun secondIsCancelledBefore300Millis() = runTest {
    val completed = mutableListOf<String>()
    val cleanupNames = mutableListOf<String>()
    val onCleanup: (String) -> Unit = { name -> cleanupNames += name }
    val first = launch { delay(100); completed += "first" }
    val second = launch { runSecond(300L, completed, onCleanup) }
    runCurrent()
    advanceTimeBy(100)
    runCurrent()
    assertEquals(listOf("first"), completed)
    assertEquals(emptyList<String>(), cleanupNames)
    second.cancelAndJoin()
    first.join()
    assertTrue(second.isCancelled)
    assertTrue(second.isCompleted)
    assertEquals(listOf("first"), completed)
    assertEquals(listOf("second"), cleanupNames)
    advanceUntilIdle()
    assertEquals(listOf("first"), completed)
    assertEquals(listOf("second"), cleanupNames)
}
```

若原文件尚未显式导入，补import kotlinx.coroutines.cancelAndJoin。先运行新方法，再运行原测试类。

## 3～5 分钟练习

取消后继续推进虚拟时间，second应补写到completed吗？

## 参考答案

不应；delay取消会跳过正常追加，但finally同步清理仍只执行一次。正常300L用例最终才有first/second。
