# FDE：业务与 AI 交付课程

FDE（Forward Deployed Engineer）深入客户的实际业务，把需求、数据、软件与 AI 能力连接起来，负责从问题发现到上线交付的完整过程。本路线以业务与 AI 落地为方向，用中文短课练习可交付的工程能力。

## 第一版目标

- 目标课数：140 节。
- 完结标准：完成基础、核心能力、综合项目、工程化与发布四个阶段。
- 每个有效更新日推进一课，每课只增加一个主要知识点，包含最小代码或操作示例、3～5 分钟练习、参考答案、具体衔接、时效校验和官方参考。
- 学习案例从虚构的“客服工单回复助手”起步，逐步形成问题卡、业务流程、数据接口、AI 原型、验收材料和交付文档。

## 开篇衔接安排

1. 把客户诉求写成业务问题卡。
2. 根据同一张问题卡设计客户访谈问题。
3. 根据访谈材料梳理客服当前的工单处理流程。
4. 标出流程中的使用者、业务负责人和系统负责人。
5. 找到流程所需的数据来源并识别待确认的数据条件。
6. 根据已确认的流程与数据条件，细化试点的验收标准。

以上是后续课题计划；已生成课程只列在下方目录。开篇不要求模型账号或开发环境。进入代码课时会先讲解必需的语言、配置和工具，也可结合本站 Python、AI 应用与智能体路线学习。

### 贯穿项目的交付记录

从问题卡逐项补齐以下记录，尚未学习或没有证据的栏位允许留空并标为待确认；不要求开篇一次写完。这是本站原创模板，不是对方课程的作业模板。

```text
记录编号：客服助手-001
业务问题：客服查资料并起草回复耗时较长
依据及缺口：当前只有模拟访谈；实际耗时、样本和数据权限待确认
范围与非目标：先辅助起草并由人工确认；自动发送未获确认
产品能力差距：检索、工单读取、草稿生成分别核对已有/配置/适配/新增
角色与确认：使用、数据授权、试点批准和验收责任分别核对
指标口径：开始/结束时间、工单类型、统计窗口、质量检查方法待确认
变更记录：新增诉求 -> 范围/数据/权限/成本/评估影响 -> 确认结论与版本
系统证据：正常、缺文档、过期文档、越权请求分别记录输入和结果
使用证据：谁实际使用、草稿被采用或被拒绝、拒绝原因
业务证据：在可比样本中比较耗时与质量；说明其他变化和归因限制
交接与沉淀：运行/停止方法、责任人、客户配置、可复用部分及前提
```

后续验收不把三类证据混成一个总分：系统评估通过不代表有人使用，使用增加也不直接证明业务改善；越权等阻断项不能被平均分抵消。回归比较要记录样本、规则和模型版本，按预先约定的分组门槛判断，不将一次模型得分上升写成稳定改善。上线和业务动作仅在后续课程明确的模拟环境中练习。
