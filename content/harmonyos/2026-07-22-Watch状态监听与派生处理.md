# 第 15 课：@Watch 状态监听与派生处理

- 日期：2026-07-22
- 知识点：`@Watch`
- 适用场景：某个状态变化后，需要同步更新提示文案、派生字段或执行轻量联动逻辑，但 UI 仍然由状态结果驱动

承接上一课的 `@Provide` / `@Consume`：上一课解决了“状态如何在组件树里共享”；这一课继续解决“状态变化后，怎样在数据层做联动处理”，而不是在点击事件里到处手写重复逻辑。

## 1. `@Watch` 用来监听状态变化

`@Watch('onXxxChange')` 可以挂在 `@State`、`@Link`、`@Prop` 等状态字段上。当这个字段变化时，会调用对应方法。  
它适合处理“基于新值再更新一个派生结果”的场景，例如：

```text
切换开关
-> 状态值变化
-> Watch 方法收到新值
-> 更新说明文案
-> UI 渲染最新文案
```

重点仍然是：`@Watch` 负责补充数据处理，不直接替代 UI 渲染。

## 2. 最小示例

```ts
@Entry
@Component
struct NotificationPage {
  @State @Watch('onNoticeChanged') noticeEnabled: boolean = false;
  @State noticeLabel: string = '通知已关闭';

  onNoticeChanged(): void {
    this.noticeLabel = this.noticeEnabled ? '通知已开启' : '通知已关闭';
  }

  build() {
    Column({ space: 16 }) {
      Text(this.noticeLabel)
        .fontSize(22)

      Button('切换通知状态')
        .onClick(() => {
          this.noticeEnabled = !this.noticeEnabled;
        })
    }
    .width('100%')
    .height('100%')
    .justifyContent(FlexAlign.Center)
  }
}
```

这里真正驱动界面的是 `noticeLabel`。  
`@Watch` 的作用是：`noticeEnabled` 变化后，把派生文案集中收口到 `onNoticeChanged()`，而不是把同样的判断散落在多个点击事件里。

## 3～5 分钟练习

把示例改成“在线状态”练习：

1. 保留一个布尔状态 `online`，默认值为 `false`。
2. 再保留一个字符串状态 `statusText`，默认值为 `离线`。
3. 用 `@Watch` 在 `online` 变化时，把 `statusText` 更新成 `在线` 或 `离线`。
4. 页面上显示 `statusText`，按钮点击后切换在线状态。

## 参考答案

```ts
@Entry
@Component
struct StatusPage {
  @State @Watch('onOnlineChanged') online: boolean = false;
  @State statusText: string = '离线';

  onOnlineChanged(): void {
    this.statusText = this.online ? '在线' : '离线';
  }

  build() {
    Column({ space: 16 }) {
      Text(this.statusText)

      Button('切换在线状态')
        .onClick(() => {
          this.online = !this.online;
        })
    }
  }
}
```

## 与上一课的联系

上一课强调“状态放在哪一层共享”；这一课补上“状态变化后怎样集中处理派生结果”。后面学表单校验、搜索条件联动或更复杂的数据模型时，`@Watch` 能帮助你把联动逻辑收在状态层，而不是散落在 UI 事件里。
