# 第 30 课：在tearDown释放测试持有引用

- 日期：2026-10-21
- 课程序号：第 30 课
- 知识点：每项测试之后的实例清理

## 用途或适用场景

让详情测试的内存夹具具有完整的准备与清理边界。

## 核心概念

实例 -tearDown 在每项测试结束后执行；在调用父类清理前释放本测试类持有的引用。ARC 下赋 nil 不保证对象立刻销毁，不手工调用 dealloc 或 release。

## 最小代码或操作示例

在第 29 课 DetailTextTests 的 @implementation 内、@end 前追加；setUp、属性、两个测试与夹具不变：

```objective-c
- (void)tearDown {
    self.plainItem = nil;
    self.detailedItem = nil;
    [super tearDown];
}
```

继续用 Product > Test 运行原无宿主 Objective-C 测试 target。

## 3～5 分钟练习

在 setUp、两项测试和 tearDown 加临时断点，记录顺序；结束后移除断点。

## 参考答案

每项各有 setUp → 当前 test → tearDown；顺序不要假设 testMissingDetail 一定先于另一项。清空测试引用不会修改 DetailText 的业务实现。
