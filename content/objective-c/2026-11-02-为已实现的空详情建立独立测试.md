# 第 38 课：为已实现的空详情建立独立测试

- 日期：2026-11-02
- 课程序号：第 38 课
- 知识点：空字符串不等于可选方法缺失

## 用途或适用场景

验证可选详情已实现且返回空字符串的既定语义。

## 核心概念

原DetailText按是否实现可选方法选择分支；已实现但返回空字符串时，应保留空字符串。新增测试不引入共享夹具，也不改变默认详情语义。

## 最小代码或操作示例

沿第36课独立起点及第37课同版隔离记录，在DetailTextTests.m原DetailFixture之后、测试类之前增加：

```objective-c
@interface EmptyDetailFixture : DetailFixture
@end
@implementation EmptyDetailFixture
- (NSString *)detailText { return @""; }
@end
```

在原DetailTextTests的@implementation内追加，保留原setUp/tearDown及两个测试：

```objective-c
- (void)testImplementedEmptyDetail {
    EmptyDetailFixture *item = [[EmptyDetailFixture alloc] init];
    XCTAssertEqualObjects(DetailText(item), @"");
}
```

沿原XCTest/LessonDetails.h、ARC及无宿主target；先独立运行新项，再运行整类。DetailText生产实现不变。

## 3～5 分钟练习

为让空字符串“好看”而改成默认“暂无详情”，会违反哪个既定约定？

## 参考答案

违反第25课实现者返回内容保持原样的约定；本例实现了detailText，不能按未实现分支处理。
