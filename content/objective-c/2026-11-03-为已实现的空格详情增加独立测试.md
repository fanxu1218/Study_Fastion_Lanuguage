# 第 39 课：为已实现的空格详情增加独立测试

- 日期：2026-11-03
- 课程序号：第 39 课
- 知识点：可选方法返回文本的原样保留

## 用途或适用场景

区分空格文本与方法未实现的默认分支。

## 核心概念

detailText已经实现时，两个空格也是实现者提供的字符串。DetailText不应擅自裁剪或替换；用独立夹具验证，不共享可变实例。

## 最小代码或操作示例

沿第37课测试隔离和第38课EmptyDetailFixture，在原DetailFixture之后、测试类之前新增：

```objective-c
@interface WhitespaceDetailFixture : DetailFixture
@end
@implementation WhitespaceDetailFixture
- (NSString *)detailText { return @"  "; }
@end
```

在DetailTextTests的@implementation内追加：

```objective-c
- (void)testImplementedWhitespaceDetail {
    WhitespaceDetailFixture *item = [[WhitespaceDetailFixture alloc] init];
    XCTAssertEqualObjects(DetailText(item), @"  ");
}
```

沿原ARC、XCTest/LessonDetails.h和无宿主target；保留setUp/tearDown及已有三项。先独立运行本项，再运行整类，不改DetailText。

## 3～5 分钟练习

若先trim再把空格改成暂无详情，哪一项既定行为被改变？

## 参考答案

实现者返回内容的原样保留被改变；本项应失败。方法存在与字符串看似空白是不同判断。
