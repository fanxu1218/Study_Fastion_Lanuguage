# 第 41 课：从详情失败项提取最小输入记录

- 日期：2026-11-05
- 课程序号：第 41 课
- 知识点：夹具实现与实际返回的对应

## 用途或适用场景

定位四类详情测试中究竟哪种输入失败。

## 核心概念

方法缺失、实现后返回空串、实现后返回空格是三种不同起点。报告须绑定实际夹具类和同一源码，不从默认文案猜方法有没有实现。

## 最小代码或操作示例

沿第39课WhitespaceDetailFixture和第40课整类报告，在Xcode原无宿主ARC测试target只读操作：

```text
1. 选一条实际失败项；没有失败则选testImplementedWhitespaceDetail作正常定位练习。
2. 从测试源码读夹具类、detailText实现及固定期望，保留完整测试名。
3. 从同轮断言读DetailText(item)实际值；报告未给则在调用位置调试读取，不改变量。
4. 并列原输入类 / 是否实现方法 / 返回内容 / 固定期望 / 实际结果。
5. 保留setUp/tearDown及四类原测试；没有XCTest环境只填能从源码确认的栏。
```

不trim、不改DetailText或共享可变夹具，未执行结果保持未验证。

## 3～5 分钟练习

空格夹具失败，能直接把它归为未实现可选方法吗？

## 参考答案

不能，先核对该夹具的detailText实现和实际返回。它已实现并返回两个空格，与默认分支不同。
