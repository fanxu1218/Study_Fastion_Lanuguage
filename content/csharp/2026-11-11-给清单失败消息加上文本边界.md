# 第 46 课：给清单失败消息加上文本边界

- 日期：2026-11-11
- 课程序号：第 46 课
- 知识点：插值字符串中的实际与期望

## 用途或适用场景

让第45课trailing-space失败能显示具体文本差异。

## 核心概念

插值字符串把变量值放入消息；方括号标识首尾边界，但字符串内换行仍实际换行，并非Python的repr。诊断不改变比较规则。

## 最小代码或操作示例

沿第44课五行foreach和第45课反例，将原CheckTextCase方法替换为：
```csharp
static void CheckTextCase(string name, string actual, string expected)
{
    if (actual != expected)
        throw new InvalidOperationException(
            $"清单检查失败：{name}; actual=[{actual}]; expected=[{expected}]");
}
```
先运行恢复正确期望的原五行，保留Main固定5与循环后return cases.Count。再仅在反例副本复用第45课错误期望，观察后恢复；沿原.NET10、System与Collections.Generic，不新增包。

## 3～5 分钟练习

为什么该消息可能跨多行，方括号后也有多个右括号？

## 参考答案

actual/expected中的换行和原有效行方括号都按原文保留；最外层边界属于诊断。不要把它误当转义表示或据此删原空格。
