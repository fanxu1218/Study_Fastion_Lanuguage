# 第 43 课：用预期panic检查未命中辅助方法

- 日期：2026-11-05
- 课程序号：第 43 课
- 知识点：should_panic与消息子串限定

## 用途或适用场景

把上一课手动制造的失败变成一项可重复的辅助方法检查。

## 核心概念

标记should_panic的测试要求发生panic；expected进一步限定消息含指定子串，减少错误来源混淆。这是检查测试辅助方法，不改变业务搜索错误模型。

## 最小代码或操作示例

沿第41课失败消息和第42课报告定位，在原assert_missing可访问的同一测试作用域追加，原八项不动：

```rust
#[test]
#[should_panic(expected = "expected no match")]
fn assert_missing_rejects_a_match() {
    assert_missing(&[3, 8, 5, 8], 8);
}
```

切片实际包含8，辅助方法应报告expected no match。先cargo test -- --list读完整名称，再用该名称配--exact执行，确认1项实际运行；最后cargo test核对原八项及新增项共九项。find_last、SearchError和辅助方法原文保持。

## 3～5 分钟练习

若把target改成9，为什么本测试反而应失败？

## 参考答案

9不存在，assert_missing正常返回，没有发生所要求的panic。测试不能只标should_panic而不核对预期消息。
