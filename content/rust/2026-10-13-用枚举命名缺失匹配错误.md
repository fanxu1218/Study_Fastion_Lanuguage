# 第 27 课：用枚举命名缺失匹配错误

- 日期：2026-10-13
- 课程序号：第 27 课
- 知识点：错误 `enum` 与已有 `Option::ok_or`

## 用途或适用场景

把缺失匹配的原因保存为明确的类型成员，供后续调用方按原因处理。

## 核心概念

上一课的错误是 `"score not found"`；本课只把它替换为 `SearchError::NotFound`。`ok_or` 的成功分支仍然保留已有 `Match`，错误枚举不会改变搜索位置或分值。本课只定义一种错误，不提前增加其他错误条件。

## 最小代码或操作示例

把下面枚举放到第 25 课的 `Match` 定义之后，在第 26 课已有 `found` 后替换错误值：

```rust
enum SearchError { NotFound }

// found 的既有类型是 Option<Match>。
let checked = found.ok_or(SearchError::NotFound);
match checked {
    Ok(item) => println!("{}: {}", item.index, item.value),
    Err(SearchError::NotFound) => println!("score not found"),
}
```

保留第 25 课 `struct Match { index: usize, value: i32 }` 和生成 `found` 的代码；`match` 是第 9 课已学的分支。

## 3～5 分钟练习

分别让原搜索命中与未命中；观察成功输出和缺失输出。不要用 `unwrap` 强行取出结果。

## 参考答案

命中时仍输出原索引和分值；未命中时进入 `Err(SearchError::NotFound)`，输出 `score not found`。`checked` 的错误类型现在是 `SearchError`。

## 与上一课的联系

继承第 25 课的 `Match` / `found` 以及第 26 课的 `ok_or`；本课只新增 `SearchError` 枚举来替换字符串错误；下一课可把这段 `Result<Match, SearchError>` 的生成步骤收进搜索函数。
