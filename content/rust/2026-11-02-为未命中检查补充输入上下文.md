# 第 40 课：为未命中检查补充输入上下文

- 日期：2026-11-02
- 课程序号：第 40 课
- 知识点：panic消息保留搜索条件

## 用途或适用场景

在缺失搜索意外命中时，从失败报告直接恢复输入。

## 核心概念

未命中辅助方法在意外Ok时必须失败。给panic附上切片与目标值，可定位哪个输入违背契约；不为业务返回类型增加额外trait。

## 最小代码或操作示例

沿第38课运行方式及第39课命中消息，只替换第32课原assert_missing，保留全部八项测试名：

```rust
fn assert_missing(scores: &[i32], target: i32) {
    match find_last(scores, target) {
        Err(SearchError::NotFound) => (),
        Ok(_) => panic!("expected no match: scores={:?}, target={}", scores, target),
    }
}
```

find_last、SearchError及assert_found不变。在原Cargo目录先cargo test empty_slice_is_missing -- --exact，再cargo test；按原清单确认目标实际执行1项。

## 3～5 分钟练习

将原无目标用例的9临时改成8，消息应提供什么？随后恢复。

## 参考答案

应失败并带原测试名、scores及target=8；恢复9后目标和全量八项通过。不能把Ok分支改为空操作。
