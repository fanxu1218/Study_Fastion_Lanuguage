# 第 34 课：为固定搜索表增加用例名称

- 日期：2026-10-23
- 课程序号：第 34 课
- 知识点：表格失败输出与具名输入的关联

## 用途或适用场景

为固定搜索表增加用例名称。

## 核心概念

测试默认捕获println!输出；某行断言失败时，报告会显示此前已执行到的用例名。它不让表内每行成为独立测试，失败后后续行仍不执行。

## 最小代码或操作示例

只替换第33课finds_last_in_fixed_cases，保留assert_found和所有其他测试：

```rust
#[test]
fn finds_last_in_fixed_cases() {
    let cases: &[(&str, &[i32], i32, usize)] = &[
        ("single", &[8], 8, 0),
        ("all-equal", &[8, 8, 8], 8, 2),
        ("separated", &[8, 3, 8], 8, 2),
    ];
    for &(name, scores, target, expected_index) in cases {
        println!("checking case: {}", name);
        assert_found(scores, target, expected_index);
    }
}
```

继续cargo test；单独查看通过时的输出可运行cargo test finds_last_in_fixed_cases -- --nocapture。

## 3～5 分钟练习

在练习副本把all-equal的期望2改为1，运行后查找最后一条用例日志，再恢复2。

## 参考答案

失败报告应关联到all-equal与索引断言；separated尚未执行。恢复后再运行同一测试，不能只看日志名便判通过。
