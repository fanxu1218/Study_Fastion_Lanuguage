# 第 29 课：为搜索函数建立命中与缺失测试

- 日期：2026-10-15
- 课程序号：第 29 课
- 知识点：#[test] 与结果分支断言

## 用途或适用场景

把上一课 find_last 的成功和缺失行为变成可重复运行的检查。

## 核心概念

测试函数加 #[test] 后由测试工具运行；失败用 panic! 或断言报告。本课把测试放在与 Match、SearchError、find_last 同一文件的顶层，继续用已学 match，不要求提前学习模块、Debug 或 PartialEq 派生。

## 最小代码或操作示例

保留第 28 课三个声明，在它们之后、main 外追加：

```rust
#[test]
fn finds_last_match() {
    match find_last(&[3, 8, 5, 8], 8) {
        Ok(item) => {
            assert_eq!(item.index, 3);
            assert_eq!(item.value, 8);
        }
        Err(SearchError::NotFound) => panic!("expected a match"),
    }
}

#[test]
fn reports_missing_match() {
    match find_last(&[3, 8, 5, 8], 9) {
        Err(SearchError::NotFound) => (),
        Ok(_) => panic!("expected NotFound"),
    }
}
```

在原 Cargo 项目目录执行 `cargo test`；已有 main 保留。assert_eq! 比较整数，失败时使测试失败，() 表示该分支无需操作。

## 3～5 分钟练习

把缺失测试输入改为空切片，仍查 9；再临时把命中索引期望改为 0，观察失败后恢复。

## 参考答案

原两项及空切片测试通过；错误期望索引使命中测试失败。无需 unwrap，也没有要求自定义类型可直接比较。
