# 第 52 课：补取一个反例的同名panic来源

- 日期：2026-11-18
- 课程序号：第 52 课
- 知识点：精确筛选与触发行对应

## 用途或适用场景

补齐第51课表中一个缺panic位置的反例。

## 核心概念

测试名、实际运行数和panic行共同限定来源；should_panic的ok不能单独说明目标断言已触发。

## 最小代码或操作示例

沿第50课副本与第51课表，在原Cargo个人工程：
```text
1. 只选一个缺来源的原反例，固定输入、完整名称和expected子串。
2. 保留原实现和断言，运行下列命令，将完整名称替换为该项真实值。
3. 核对实际运行1项，保存panic文件/行和消息，判断是否来自原目标断言。
4. 附回本轮行；准备阶段触发的panic仍记来源不符，不修改expected迎合它。
```
```sh
cargo test 完整名称 -- --exact --show-output
```
无工程只整理待执行项；不加忽略标记或catch_unwind。

## 3～5 分钟练习

命令只显示0 tests，退出成功能证明该反例的来源吗？

## 参考答案

不能；核对完整模块路径后再运行，来源栏继续待证。
