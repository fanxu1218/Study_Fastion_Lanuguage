# 第 55 课：让命中辅助断言报告直接调用位置

- 日期：2026-11-23
- 课程序号：第 55 课
- 知识点：track_caller用于原命中辅助方法

## 用途或适用场景

沿第54课调用位置传播，让assert_found的报告也可对应到直接测试调用。

## 核心概念

属性不改变Result或比较值；assert_eq!或panic!仍在原分支触发，报告位置可指向调用者。保留调用行与原分支两个信息。

## 最小代码或操作示例

在原Cargo个人副本，仅在第39/41课现有assert_found声明正上方插入：
```rust
#[track_caller]
```
第54课assert_missing属性及原十项不动。先运行全部测试；仅在个人副本把fixed_all_equal_scores的expected_index由原2临时改为1，用其真实完整模块名执行：
```sh
cargo test 完整名称 -- --exact --show-output
```
占位名称须替换，确认实际运行1项并预期失败；报告应指向该测试直接调用assert_found的行，消息仍保留index/scores/target。恢复2，再执行目标和cargo test。不添加包装调用、函数指针或catch_unwind。

## 3～5 分钟练习

报告落在测试调用行，能说比较已从assert_found移到了测试里吗？

## 参考答案

不能；比较仍在原Ok分支，只有调用位置传播改变。恢复反例后检查原十项，不删除独立期望。
