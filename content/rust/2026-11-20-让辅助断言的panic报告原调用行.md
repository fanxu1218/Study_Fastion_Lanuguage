# 第 54 课：让辅助断言的panic报告原调用行

- 日期：2026-11-20
- 课程序号：第 54 课
- 知识点：track_caller标注直接调用来源

## 用途或适用场景

沿第53课已对应的触发语句，让assert_missing的报告更接近发起检查的位置。

## 核心概念

#[track_caller]改变所传播的调用位置；它不改变find_last结果或should_panic消息匹配。此处只针对assert_missing直接触发panic的分支，仍保留原函数内触发点和本轮调用链。

## 最小代码或操作示例

在原Cargo个人副本，用下列完整定义替换原assert_missing，仅新增属性：
```rust
#[track_caller]
fn assert_missing(scores: &[i32], target: i32) {
    match find_last(scores, target) {
        Err(SearchError::NotFound) => (),
        Ok(_) => panic!("expected no match: scores={:?}, target={}", scores, target),
    }
}
```
保留原十项与expected子串，使用本项目真实完整名称运行原assert_missing_rejects_a_match：
```sh
cargo test 完整名称 -- --exact --show-output
cargo test
```
第一条将占位名称换为现有完整模块路径，核对实际1项；比较新增属性前后的panic位置，新报告应指向测试中直接调用assert_missing的行。沿用原真实工程稳定工具链，不安装新版本。

## 3～5 分钟练习

报告位置变成调用行，是否意味着panic不再来自assert_missing的Ok分支？

## 参考答案

不是；属性传播调用位置，触发逻辑仍在原Ok分支。记录调用行与原函数内分支，expected和搜索语义不变。
