# 第 44 课：用预期panic检查命中辅助方法

- 日期：2026-11-06
- 课程序号：第 44 课
- 知识点：为另一错误分支限定panic消息

## 用途或适用场景

让意外未命中的诊断也能重复验证。

## 核心概念

should_panic要求函数发生panic，expected只匹配消息子串。本例检查assert_found的Err分支，不改变find_last或SearchError。

## 最小代码或操作示例

沿第42课报告及第43课预期panic，在assert_found可访问的同一测试作用域追加：
```rust
#[test]
#[should_panic(expected = "expected a match")]
fn assert_found_rejects_a_missing_value() {
    assert_found(&[3, 8, 5, 8], 9, 0);
}
```
9不在切片中，应进入第41课带scores/target/expected_index的错误消息。cargo test -- --list读取完整名称，再以完整名称配--exact执行1项，最后cargo test核对原八项、上一课与本课共十项。

## 3～5 分钟练习

expected_index=0是否表示9应该在索引0？

## 参考答案

不是，它是供命中比较使用的期望；本例应先因9未命中进入Err分支，检查的正是该诊断，不应拿0伪造命中。
