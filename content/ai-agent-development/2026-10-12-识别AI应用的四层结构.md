# 第 1 课：识别 AI 应用的四层结构

- 日期：2026-10-12
- 课程序号：第 1 课
- 知识点：AI 应用的界面、业务服务、智能体编排与模型四层职责

## 用途或适用场景

开始设计聊天助手、知识问答或业务智能体前，先确认每一层负责什么，避免把整个产品误解成一次模型调用。

## 核心概念

一个最小 AI 应用可以拆成四层：界面接收用户输入；业务服务负责身份、数据与接口；智能体编排决定何时调用模型、工具或知识库；模型根据上下文生成或判断。模型不是业务数据库，也不应直接拥有支付、删除等高风险权限。

## 最小代码或操作示例

```text
用户界面 -> 业务 API -> Agent（模型 + 工具 + 知识库） -> 模型服务
                         |
                         +-> 业务工具（查询订单、创建工单）
```

以“查询订单进度”为例：界面提交订单号，业务 API 校验身份，Agent 选择订单查询工具，工具从业务系统读取事实，模型只负责把结果组织成易读回答。

## 3～5 分钟练习

把“企业知识问答”拆成四层，每层写出一个职责，并标出知识库属于哪一层的可调用资源。

## 参考答案

- 界面：接收问题并展示答案。
- 业务服务：鉴权、记录请求、限制访问范围。
- 智能体编排：决定检索知识库后再调用模型。
- 模型：基于检索结果生成回答。
- 知识库：是编排层调用的外部资源，不是模型参数本身。
