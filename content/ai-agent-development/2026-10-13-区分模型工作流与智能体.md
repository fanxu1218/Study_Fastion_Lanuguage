# 第 2 课：区分模型、工作流与智能体

- 日期：2026-10-13
- 课程序号：第 2 课
- 知识点：根据“谁决定下一步”区分模型调用、工作流与智能体

## 用途或适用场景

继续设计上一课的订单查询助手，判断任务是否需要动态选择工具，避免在需求尚简单时引入不必要的编排。

## 核心概念

模型调用接收输入并生成输出；工作流由开发者预先规定步骤或分支；智能体让模型依据当前信息决定下一步和工具使用。工作流中也可以调用模型，判断标准是控制流程的方式。

三种方式都能放在第 1 课的应用架构内，身份校验和工具权限仍由业务服务执行。本课只比较控制方式，不安装框架。

## 最小代码或操作示例

在文本编辑器中复制这三条教学流程，标出决定下一步的角色：

```text
同一任务：用户查询订单 A100 的进度

模型调用：把已查得的订单状态交给模型 -> 生成易读说明
工作流：校验身份 -> 查询订单 -> 把查询结果交给模型 -> 展示说明
智能体：在授权工具范围内，根据问题决定先查询订单还是查询物流；
        读到工具结果后决定是否继续查询，然后组织回答
```

这里的订单与流程是虚构示例。模型生成的文字不能代替订单系统的查询事实；动态选择步骤也不代表工具获得了额外权限。

## 3～5 分钟练习

给下面两种需求选择方式，并各写一句理由：①所有订单都按固定步骤查询后解释；②有的问题问订单状态，有的问题还需要根据结果查询物流。只依据流程是否需要动态选择作判断。

## 参考答案

①可以采用工作流，查询与解释的步骤已确定。②可以考虑智能体，由模型在允许的工具中决定下一步；如果规则能够明确列出，也可以使用工作流分支，并非必须使用智能体。单独的说明生成属于一次模型调用。

## 与上一课的联系

继承第 1 课“界面 -> 业务 API -> 编排 -> 模型/工具”的架构及订单查询案例；本课只增加控制流程的选择标准。练习得到的流程可以作为下一课观察模型输入、输出与 Token 的起点；本课不实现工具调用循环。
