# 第 28 课：单独列出待执行的朗读用例

- 日期：2026-10-15
- 课程序号：第 28 课
- 知识点：从原始记录筛选 actual=null

## 用途或适用场景

在已有平台失败分组之外，为尚未执行的设备检查列出待办。

## 核心概念

待执行项从 caseRows 派生，不能从 failedRows 推断；前者保留全部原始观察，后者已经排除了 null。不把空字符串当未执行，空字符串可能是实测没有播报。

## 最小代码或操作示例

接在第 27 课 failedByPlatform 后，保留原 A11yCheck 与 caseRows：

```ts
const pendingRows = caseRows.filter(row => row.actual === null);
console.log(pendingRows);
```

不写回 actual，不增加手工维护的 pending 标记。

## 3～5 分钟练习

在教学副本放入三条模拟记录：actual=null、actual=expected、actual="" 且 expected 非空；检查待办和原失败列表。

## 参考答案

只有 null 项进入 pendingRows；与期望相同项通过；空字符串项是已执行不一致，进入 failedRows。三项原始记录都留在 caseRows，模拟数据不代表双平台实测。
