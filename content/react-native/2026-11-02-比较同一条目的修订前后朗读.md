# 第 39 课：比较同一条目的修订前后朗读

- 日期：2026-11-02
- 课程序号：第 39 课
- 知识点：同环境同业务id的前后证据

## 用途或适用场景

依据设备记录比较一条无障碍提示修订的实际效果。

## 核心概念

前后比较需要同一业务id、原步骤和TalkBack条件。实际朗读随构建关联；没有旧同条件记录时，不能把另一环境的结果拼成修复证明。

## 最小代码或操作示例

沿第37课R-01关联和第38课单项新构建观察，在本地回归记录中比较：

```text
1. 选第38课已执行的业务id，保留修订构建及原实际朗读。
2. 找同id、同系统/TalkBack版本、语言、steps的旧A记录；缺项则注明无法严格比较。
3. 并列旧/新实际label、hint来源及朗读原文，不改caseRows或复制expected。
4. 只对原确认差异写改善 / 未改善 / 材料不足，附同次相邻id观察。
5. 其余环境和未执行设备保持原状态，不安装覆盖旧构建凑证据。
```

不加announce、不复制业务状态；本课整理已有设备证据，无设备条件则仅列比较计划。

## 3～5 分钟练习

新记录正确，但旧记录的id未知，能宣布同条目修订前后通过吗？

## 参考答案

不能；旧记录无法对应目标身份，只能保留新构建本次观察范围。
