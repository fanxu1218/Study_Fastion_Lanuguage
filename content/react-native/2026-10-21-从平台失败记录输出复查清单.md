# 第 31 课：从平台失败记录输出复查清单

- 日期：2026-10-21
- 课程序号：第 31 课
- 知识点：保留原始观察的逐项输出

## 用途或适用场景

让 Android 失败数量能追溯到版本、步骤和期望/实际。

## 核心概念

数量只说明规模；复查必须保留原始行的环境与观察。沿 failedRows 筛选平台，不改 actual，空串仍是已执行的观察，null 不进入失败清单。

## 最小代码或操作示例

接在第 30 课平台统计后，复用原 A11yCheck、caseRows 和 failedRows：

```ts
const androidFailures = failedRows.filter(row => row.platform === 'android');
for (const row of androidFailures) {
  console.log({
    platform: row.platform,
    readerVersion: row.readerVersion,
    steps: row.steps,
    expected: row.expected,
    actual: row.actual,
  });
}
```

不追加手工 result 或失败计数，不把待执行项移成失败。

## 3～5 分钟练习

沿上一课模拟数据运行，再把 Android 那行 actual 改为 null 后重新执行全部派生步骤。

## 参考答案

原空串行会完整输出；改为 null 后清单为空，Android pending 增加。需重新从 caseRows 派生 failedRows，旧数组不会自动响应变量赋值；这些仍是模拟结果。
