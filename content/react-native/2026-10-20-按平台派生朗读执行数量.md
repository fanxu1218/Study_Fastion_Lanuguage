# 第 30 课：按平台派生朗读执行数量

- 日期：2026-10-20
- 课程序号：第 30 课
- 知识点：在平台子集上复用汇总规则

## 用途或适用场景

分别看到iOS与Android待执行和失败数量。

## 核心概念

先从 caseRows 按平台筛选，再使用 actual=null 的相同规则计数。一个平台没有记录时只表示覆盖为空，不能写成该平台已通过。

## 最小代码或操作示例

接在第 29 课汇总后，保留 A11yCheck/caseRows 和原筛选：

```ts
for (const platform of ['ios', 'android']) {
  const platformRows = caseRows.filter(row => row.platform === platform);
  const platformPending = platformRows.filter(row => row.actual === null).length;
  const platformFailed = platformRows.filter(row =>
    row.actual !== null && row.actual !== row.expected).length;
  const platformExecuted = platformRows.length - platformPending;
  console.log({platform, total: platformRows.length,
    pending: platformPending, executed: platformExecuted,
    passed: platformExecuted - platformFailed, failed: platformFailed});
}
```

不写回原始观察；保留每项版本与步骤用于复查。

## 3～5 分钟练习

用模拟数据：iOS一条未执行、一条相符；Android一条actual为空字符串且期望非空。

## 参考答案

iOS为total2/pending1/executed1/passed1/failed0；Android为1/0/1/0/1。空串属于已执行不一致，模拟计数不代表真实双平台朗读结果。
