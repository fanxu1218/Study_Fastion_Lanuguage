# 第 27 课：按平台分组朗读失败记录

- 日期：2026-10-14
- 课程序号：第 27 课
- 知识点：从 failedRows 派生平台分组

## 用途或适用场景

把上一课已执行的失败项分给 iOS 与 Android 两组，便于安排复测。

## 核心概念

分组仍从 failedRows 派生，不复制人工维护的 pass/fail；保留每项 readerVersion、steps、expected、actual。两个平台必须各自验证，某一组为空不等于该平台通过。

## 最小代码或操作示例

接在第 26 课 failedRows 后，沿用原 A11yCheck 和 caseRows：

```ts
const failedByPlatform = {
  ios: failedRows.filter(row => row.platform === 'ios'),
  android: failedRows.filter(row => row.platform === 'android'),
};
console.log(failedByPlatform);
```

平台值继续使用类型定义中的小写 ios/android；不改原始实际观察。

## 3～5 分钟练习

在教学副本加入 iOS 已执行失败、Android 已执行失败和 Android 未执行三条模拟记录；标清模拟后再筛选和分组。

## 参考答案

两个失败组各一项，actual=null 不进入任何失败组，仍留在 caseRows。设备尚未执行的空组只能解释为“没有已记录失败”，不能解释为已通过。

## 与上一课的联系
