# 第 24 课：为课程查询建模加载状态

- 日期：2026-10-12
- 课程序号：第 24 课
- 知识点：Loading/Ready/Missing 状态与查询结果的映射

## 用途或适用场景

把“开始查询”与“已经查询但没找到”明确区分，界面下一课才能完整渲染。

## 核心概念

LessonUiState 是互斥状态。沿用第 22 课仓库与 lessonId，在每次查询的流内先发送 Loading，再把已有 nullable Lesson 映射为 Ready 或 Missing；不把 Loading 当作空课程。模拟仓库瞬时返回，因此不承诺肉眼能看到加载文案。

## 最小代码或操作示例

```kotlin
import kotlinx.coroutines.flow.map
import kotlinx.coroutines.flow.onStart

sealed interface LessonUiState {
    data object Loading : LessonUiState
    data class Ready(val title: String) : LessonUiState
    data object Missing : LessonUiState
}
// 放在第 22 课已显式 @OptIn 的 LessonViewModel 内。
// 用它替换第 23 课的 message；不再同时维护另一份文案流。
val uiState: Flow<LessonUiState> = lessonId.flatMapLatest { id ->
    repository.observeLesson(id)
        .map<Lesson?, LessonUiState> { item ->
            if (item == null) LessonUiState.Missing else LessonUiState.Ready(item.title)
        }
        .onStart { emit(LessonUiState.Loading) }
}
```

## 3～5 分钟练习

用 python 与不存在的 ID 分别收集 uiState，记录收到的类型顺序。

## 参考答案

python 收到 Loading→Ready("Python 入门")；未知 ID 收到 Loading→Missing。这里未新增网络异常语义；同步仓库也会发出加载状态，但可能不产生可见的一帧。

## 与上一课的联系

继承第 23 课 nullable Lesson 的命中/空结果分支和第 22 课 lessonId 查询；本课只把结果连同查询开始阶段统一成 LessonUiState；下一课在原 Activity 生命周期收集块中穷尽渲染三种状态。
