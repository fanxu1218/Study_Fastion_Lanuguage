# 第 49 课：为第三次保存建立独立拒绝用例

- 日期：2026-11-16
- 课程序号：第 49 课
- 知识点：同一提交序列的成功与拒绝分支

## 用途或适用场景

保留第48课R8成功路径，新增R9覆盖第三次拒绝。

## 核心概念

每个测试建立自己的first/second/third；拒绝时只核对本次错误和交互恢复，不复用另一测试的Promise。

## 最小代码或操作示例

在同一测试文件复制第48课完整R8为独立R9（各自创建并render一次），保留第46、47课全部前置步骤及第三次pending。仅将R9末尾third.resolve及其成功断言整段替换为：
```jsx
await act(async () => {
  third.reject(new Error('第三次保存失败'));
});
expect(screen.getByRole('alert').textContent).toBe('第三次保存失败');
expect(screen.getByRole('status').textContent).toBe('');
expect(input.value).toBe('React 第三稿');
expect(input.disabled).toBe(false);
expect(screen.getByRole('button', {name: '保存'}).disabled).toBe(false);
expect(calls).toEqual([
  ['l1', 'React 修订'],
  ['l1', 'React 第二稿'],
  ['l1', 'React 第三稿'],
]);
```
沿原afterEach(cleanup)，运行Vitest R1～R9；不改LessonItem。

## 3～5 分钟练习

直接把原R8改成拒绝但不保留成功用例，会失去什么？

## 参考答案

失去第三次成功回归；保留R8，R9使用独立受控结果。
