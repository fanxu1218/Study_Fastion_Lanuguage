# 第 57 课：让第五次保存失败后恢复编辑

- 日期：2026-11-26
- 课程序号：第 57 课
- 知识点：独立Promise拒绝后的交互状态

## 用途或适用场景

继续第56课同一R9中仍pending的fifth。

## 核心概念

只拒绝第五次自己的结果；await act完成更新后，错误来自本次失败，输入仍保留第五稿并可再编辑。

## 最小代码或操作示例

在第56课同一R9末尾追加，沿原act导入：
```jsx
await act(async () => {
  fifth.reject(new Error('第五次保存失败'));
});
expect(screen.getByRole('alert').textContent).toBe('第五次保存失败');
expect(screen.getByRole('status').textContent).toBe('');
expect(input.value).toBe('React 第五稿');
expect(input.disabled).toBe(false);
expect(screen.getByRole('button', {name: '保存'}).disabled).toBe(false);
expect(calls).toEqual([
  ['l1', 'React 修订'],
  ['l1', 'React 第二稿'],
  ['l1', 'React 第三稿'],
  ['l1', 'React 第四稿'],
  ['l1', 'React 第五稿'],
]);
```
保留同一render、五个受控结果、原分支及afterEach(cleanup)，运行Vitest R1～R9；不额外点击。

## 3～5 分钟练习

误拒绝已经结束的third，能代表第五次失败恢复吗？

## 参考答案

不能；fifth仍未结束。只有本次结果处理后才能检查错误、可编辑输入和恰好五次调用。
