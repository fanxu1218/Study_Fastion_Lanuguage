# 第 56 课：用独立结果提交第五稿

- 日期：2026-11-25
- 课程序号：第 56 课
- 知识点：每次保存绑定自己的受控Promise

## 用途或适用场景

从第55课已编辑的第五稿进入新的pending边界。

## 核心概念

旧fourth已经完成，不能充当第五次保存的结果；本次准备和返回fifth是一个不可拆分的提交条件。

## 最小代码或操作示例

在同一R9顶部fourth声明后添加const fifth = createControlledSave();。原onRename回调末尾的return fourth.promise替换为：
```jsx
if (calls.length === 4) return fourth.promise;
return fifth.promise;
```
在第55课同一R9末尾追加：
```jsx
fireEvent.click(screen.getByRole('button', {name: '保存'}));
expect(calls).toEqual([
  ['l1', 'React 修订'],
  ['l1', 'React 第二稿'],
  ['l1', 'React 第三稿'],
  ['l1', 'React 第四稿'],
  ['l1', 'React 第五稿'],
]);
expect(input.disabled).toBe(true);
expect(screen.getByRole('button', {name: '保存中…'}).disabled).toBe(true);
expect(screen.getByRole('status').textContent).toBe('');
expect(screen.queryByRole('alert')).toBeNull();
```
保留同一render、原四个分支结果及afterEach(cleanup)，运行Vitest R1～R9；本课不完成fifth。

## 3～5 分钟练习

只新增fifth声明却仍返回已完成fourth，能验证第五次pending吗？

## 参考答案

不能；回调必须把第5次调用映射到fifth.promise。否则新提交错误地复用了旧结果，等待边界失真。
