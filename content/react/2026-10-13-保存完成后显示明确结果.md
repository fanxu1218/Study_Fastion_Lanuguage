# 第 26 课：保存完成后显示明确结果

- 日期：2026-10-13
- 课程序号：第 26 课
- 知识点：用互斥提交状态表达保存完成

## 用途或适用场景

只在上一课保存回调成功结束之后显示“已保存”，重新编辑后撤下旧结果。

## 核心概念

把原 submitting 布尔值升级为 idle/submitting/saved 三种互斥过程状态；submitting 从 status 派生，不维护两份状态。saved 描述这次回调已完成，已保存标题继续以父 lessons 为准。错误处理沿用上一课，不提前增加网络重试或乐观更新。

## 最小代码或操作示例

```jsx
// 保留第 24 课的父 LessonList/onRename；替换 LessonItem。
function LessonItem({ item, onRename }) {
  const [draft, setDraft] = useState(item.title);
  const [error, setError] = useState('');
  const [status, setStatus] = useState('idle');
  const submitting = status === 'submitting';
  async function submit(event) {
    event.preventDefault();
    const title = draft.trim();
    if (!title) { setStatus('idle'); setError('请输入课程标题'); return; }
    setError('');
    setStatus('submitting');
    try {
      await onRename(item.id, title);
      setDraft(title);
      setStatus('saved');
    } catch (error) {
      setError(error.message);
      setStatus('idle');
    }
  }
  return <li><form onSubmit={submit}>
    <label>课程标题 <input value={draft} disabled={submitting}
      onChange={event => {
        setDraft(event.target.value); setError(''); setStatus('idle');
      }} aria-invalid={Boolean(error)}
      aria-describedby={error ? `${item.id}-error` : undefined} /></label>
    <button type="submit" disabled={submitting}>
      {submitting ? '保存中…' : '保存'}
    </button>
    {error && <p id={`${item.id}-error`} role="alert">{error}</p>}
    {status === 'saved' && <p>已保存</p>}
  </form></li>;
}
```

## 3～5 分钟练习

提交“React 入门”，等待“已保存”；再输入一个字符但先不保存。

## 参考答案

回调等待期间只显示“保存中…”；成功后出现“已保存”；重新编辑撤下结果且父标题尚未更改。失败回调不会进入 saved；400 毫秒等待仅为前课模拟。

## 与上一课的联系

继承第 25 课的提交中文字、第 24 课 await/onRename 与错误路径、draft/error；本课只增加完成结果并以互斥 status 替代布尔过程状态；下一课可使完成结果区具备非打断式无障碍通知语义。
