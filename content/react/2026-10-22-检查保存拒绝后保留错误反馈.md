# 第 32 课：检查保存拒绝后保留错误反馈

- 日期：2026-10-22
- 课程序号：第 32 课
- 知识点：异步失败回调的组件断言

## 用途或适用场景

把 R3 拒绝路径补到原 R1/R2 测试旁。

## 核心概念

拒绝的 Promise 应进入原 catch，显示真实错误并恢复编辑入口；不能出现成功通知。替身只模拟服务结果，不证明真实网络集成。

## 最小代码或操作示例

在第 31 课测试文件中追加，保留现有导入、waitFor 和 cleanup：

```jsx
test('R3 保存拒绝后显示错误而非成功', async () => {
  async function onRename() { throw new Error('模拟保存失败'); }
  render(<ul><LessonItem item={{id: 'l1', title: 'React'}}
    onRename={onRename} /></ul>);
  fireEvent.change(screen.getByRole('textbox', {name: '课程标题'}),
    {target: {value: 'React 练习'}});
  fireEvent.click(screen.getByRole('button', {name: '保存'}));
  await waitFor(() => {
    expect(screen.getByRole('alert').textContent).toBe('模拟保存失败');
  });
  expect(screen.getByRole('status').textContent).toBe('');
  expect(screen.getByRole('textbox', {name: '课程标题'}).disabled).toBe(false);
  expect(screen.getByRole('textbox', {name: '课程标题'}).value).toBe('React 练习');
});
```

执行原 Vitest 命令；LessonItem 的 catch(error.message) 和父数据源保持不变。

## 3～5 分钟练习

临时把替身改成成功返回，再运行本用例，观察失败后恢复拒绝。

## 参考答案

成功替身不能满足错误断言；原拒绝替身显示模拟保存失败、无已保存通知、草稿保留。jsdom 不验证实际布局或读屏。
