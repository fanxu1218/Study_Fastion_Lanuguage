# 第 34 课：检查保存失败后再次提交可以成功

- 日期：2026-10-26
- 课程序号：第 34 课
- 知识点：同一组件树中的失败恢复提交

## 用途或适用场景

同一组件树中的失败恢复提交，继续使用本路线的原练习。

## 核心概念

先出现真实失败反馈，再编辑并让第二次异步调用成功；成功通知必须等待本次onRename完成，不能把编辑清错直接当作保存完成。

## 最小代码或操作示例

在原R1～R4测试文件新增，沿用LessonItem、导入、waitFor和cleanup：

```jsx
test('R5 失败后重新编辑并保存成功', async () => {
  const calls = [];
  async function onRename(id, title) {
    calls.push([id, title]);
    if (calls.length === 1) throw new Error('模拟保存失败');
  }
  render(<ul><LessonItem item={{id: 'l1', title: 'React'}}
    onRename={onRename} /></ul>);
  const input = screen.getByRole('textbox', {name: '课程标题'});
  fireEvent.change(input, {target: {value: 'React 练习'}});
  fireEvent.click(screen.getByRole('button', {name: '保存'}));
  await waitFor(() => {
    expect(screen.getByRole('alert').textContent).toBe('模拟保存失败');
  });
  fireEvent.change(input, {target: {value: 'React 修订'}});
  fireEvent.click(screen.getByRole('button', {name: '保存'}));
  await waitFor(() => {
    expect(screen.getByRole('status').textContent).toBe('已保存');
  });
  expect(screen.queryByRole('alert')).toBe(null);
  expect(calls).toEqual([['l1', 'React 练习'], ['l1', 'React 修订']]);
  expect(input.disabled).toBe(false);
});
```

不重新render，不修改生产组件；替身成功不代表真实服务或父数据持久化通过。

## 3～5 分钟练习

若第二次替身也抛错，哪个成功断言应失败？

## 参考答案

等待“已保存”的断言应失败。第二次调用参数仍可记录，但调用发生不能证明成功；恢复替身后重跑。
