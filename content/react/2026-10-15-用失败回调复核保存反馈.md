# 第 28 课：用失败回调复核保存反馈

- 日期：2026-10-15
- 课程序号：第 28 课
- 知识点：以可控拒绝检查已有提交状态

## 用途或适用场景

验证同一 LessonItem 在保存失败时显示错误，并且不会宣布已保存。

## 核心概念

成功通知由 await 成功后的 saved 状态产生；拒绝回调进入已有 catch。测试替身只替换父组件保存回调，不修改子组件来伪造失败，也不提前更新父 lessons。

## 最小代码或操作示例

在练习副本的 LessonList 中，临时把原 onRename 替换为：

```jsx
async function onRename(id, title) {
  // 教学模拟失败；不写入父 lessons，没有远程请求。
  await new Promise(resolve => setTimeout(resolve, 400));
  throw new Error('教学模拟：保存失败');
}
```

保留第 26～27 课完整 LessonItem，包括 catch、错误 alert、常驻 status 区域和输入 onChange。测试后恢复原 onRename。

## 3～5 分钟练习

输入新标题并保存，等待 400 毫秒；核对错误、按钮、status 文本和父 lessons，再重新编辑。恢复成功回调后再保存一次。

## 参考答案

失败后显示模拟错误、输入与按钮可用、status 区为空、父标题未变；重新编辑清除错误。恢复成功回调后才显示已保存。此过程只验证内存模拟契约。

## 与上一课的联系

继承第 24 课父 onRename、第 26 课互斥 status 和第 27 课通知区域；本课只增加可控失败对照，不新增状态。下一课可把成功/失败检查整理为组件交互测试。
