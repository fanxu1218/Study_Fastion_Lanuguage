# 第 33 课：检查失败后重新编辑会清除旧错误

- 日期：2026-10-23
- 课程序号：第 33 课
- 知识点：异步失败到再次编辑的组件转换

## 用途或适用场景

检查失败后重新编辑会清除旧错误。

## 核心概念

先等待失败反馈真正出现，再编辑同一输入框；编辑清错不代表保存成功，仍以原onRename完成结果为准。

## 最小代码或操作示例

在原R1/R2/R3测试文件追加，沿用导入、waitFor和cleanup：

```jsx
test('R4 失败后重新编辑撤下旧错误', async () => {
  async function onRename() { throw new Error('模拟保存失败'); }
  render(<ul><LessonItem item={{id: 'l1', title: 'React'}}
    onRename={onRename} /></ul>);
  const input = screen.getByRole('textbox', {name: '课程标题'});
  fireEvent.change(input, {target: {value: 'React 练习'}});
  fireEvent.click(screen.getByRole('button', {name: '保存'}));
  await waitFor(() => {
    expect(screen.getByRole('alert').textContent).toBe('模拟保存失败');
  });
  fireEvent.change(input, {target: {value: 'React 修订'}});
  expect(screen.queryByRole('alert')).toBe(null);
  expect(screen.getByRole('status').textContent).toBe('');
  expect(input.value).toBe('React 修订');
});
```

不再render一棵新树；执行原Vitest命令。

## 3～5 分钟练习

把重新编辑移到waitFor之前，为什么不能可靠验证本课转换？

## 参考答案

此时可能尚未进入失败状态，检查不到“已有旧错误→编辑清除”的过程。应先等待失败，再触发change。
