# 第 35 课：用可控Promise检查保存期间的禁用状态

- 日期：2026-10-27
- 课程序号：第 35 课
- 知识点：异步完成前后的可控测试边界

## 用途或适用场景

用可控Promise检查保存期间的禁用状态，让本次练习的结果可以按同一条件复查。

## 核心概念

让测试替身返回暂不完成的Promise，就能稳定检查保存期间；手动完成后再验证恢复。等待由测试控制，不依赖机器是否恰好在固定毫秒内执行。

## 最小代码或操作示例

在原R1～R5文件追加。将act加入现有@testing-library/react具名导入，其他导入和cleanup保留：

```jsx
test('R6 保存未完成时禁用输入与按钮', async () => {
  let finishSave;
  const pending = new Promise(resolve => { finishSave = resolve; });
  const calls = [];
  function onRename(id, title) {
    calls.push([id, title]);
    return pending;
  }
  render(<ul><LessonItem item={{id: 'l1', title: 'React'}}
    onRename={onRename} /></ul>);
  const input = screen.getByRole('textbox', {name: '课程标题'});
  fireEvent.change(input, {target: {value: 'React 练习'}});
  fireEvent.click(screen.getByRole('button', {name: '保存'}));
  expect(input.disabled).toBe(true);
  expect(screen.getByRole('button', {name: '保存中…'}).disabled).toBe(true);
  expect(screen.getByRole('status').textContent).toBe('');
  expect(calls).toEqual([['l1', 'React 练习']]);
  await act(async () => { finishSave(); await pending; });
  await waitFor(() => {
    expect(screen.getByRole('status').textContent).toBe('已保存');
  });
  expect(input.disabled).toBe(false);
  expect(screen.getByRole('button', {name: '保存'}).disabled).toBe(false);
});
```

不改LessonItem；替身不更新父列表，本课只断言交互过程。

## 3～5 分钟练习

如果在检查禁用之前就调用finishSave，为什么可能失去本课要检查的状态？

## 参考答案

提交可能已经完成并恢复可用。应先观察未完成状态，再在act内释放Promise并检查完成状态；不能用成功回调代替真实服务验证。
