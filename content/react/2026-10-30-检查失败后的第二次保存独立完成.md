# 第 38 课：检查失败后的第二次保存独立完成

- 日期：2026-10-30
- 课程序号：第 38 课
- 知识点：同一组件的重试Promise

## 用途或适用场景

检查失败后的第二次保存独立完成，用于在已有示例中练习同一组件的重试Promise。

## 核心概念

失败恢复后再次提交应产生新的保存调用和pending状态。两次Promise分别受控，第二次成功不能靠复用已拒绝的Promise模拟。

## 最小代码或操作示例

沿第36课R7与第37课createControlledSave，在同一测试文件追加，保留原cleanup及导入：

```jsx
test('R8 失败后可独立再次保存', async () => {
  const first = createControlledSave();
  const second = createControlledSave();
  let calls = 0;
  render(<ul><LessonItem item={{id: 'l1', title: 'React'}}
    onRename={() => { calls += 1;
      return calls === 1 ? first.promise : second.promise;
    }} /></ul>);
  const input = screen.getByRole('textbox', {name: '课程标题'});
  fireEvent.change(input, {target: {value: 'React 修订'}});
  fireEvent.click(screen.getByRole('button', {name: '保存'}));
  await act(async () => {
    first.reject(new Error('模拟保存失败'));
    await first.promise.catch(() => {});
  });
  await waitFor(() => {
    expect(screen.getByRole('alert').textContent).toBe('模拟保存失败');
  });
  expect(input.value).toBe('React 修订');
  fireEvent.click(screen.getByRole('button', {name: '保存'}));
  expect(calls).toBe(2);
  expect(input.disabled).toBe(true);
  expect(screen.getByRole('button', {name: '保存中…'}).disabled).toBe(true);
  await act(async () => { second.resolve(); await second.promise; });
  await waitFor(() => {
    expect(screen.getByRole('status').textContent).toBe('已保存');
  });
  expect(input.disabled).toBe(false);
  expect(screen.getByRole('button', {name: '保存'}).disabled).toBe(false);
  expect(screen.queryByRole('alert')).toBe(null);
});
```

只新增测试，不改LessonItem；测试回调计数不是业务状态。

## 3～5 分钟练习

第二次直接返回first.promise而不创建second，会检查到什么错误？

## 参考答案

已拒绝Promise会再次失败，不能得到独立pending/成功路径。本课两个控制对象只属于这一项测试。
