# 第 40 课：核对重新编辑后的重试保存参数

- 日期：2026-11-03
- 课程序号：第 40 课
- 知识点：重试读取当次草稿

## 用途或适用场景

防止失败后重试仍提交旧文本。

## 核心概念

同一组件失败后编辑新文本，第二次回调应收到新草稿；第一次记录保持旧值。继续使用两次独立Promise，不能重建组件绕开状态转换。

## 最小代码或操作示例

沿第38课R8及第39课calls参数表，在首次拒绝和错误断言之后、第二次点击之前增加：

```jsx
fireEvent.change(input, {target: {value: 'React 第二稿'}});
expect(screen.queryByRole('alert')).toBe(null);
```

将第二次点击后的calls期望替换为：

```jsx
expect(calls).toEqual([
  ['l1', 'React 修订'],
  ['l1', 'React 第二稿'],
]);
```

其余R8顺序、独立first/second、await act、pending及成功断言不变；保留R1～R8和cleanup，不新增重复测试，不改LessonItem。

## 3～5 分钟练习

第二次仍收到React 修订，但页面显示已保存，能判本用例通过吗？

## 参考答案

不能；参数断言应失败。成功反馈仅说明回调完成，不能证明提交的是当次草稿。
