# 第 31 课：等待成功保存后的状态消息

- 日期：2026-10-21
- 课程序号：第 31 课
- 知识点：waitFor 等待异步可观察结果

## 用途或适用场景

把 R2 的成功完成提示加入原组件测试。

## 核心概念

waitFor 会重试抛错的断言，调用方必须 await。保存替身接收真实参数并成功完成；本课只覆盖子组件成功反馈，不冒充父列表更新或真实服务集成测试。

## 最小代码或操作示例

在第 30 课测试文件中，将 waitFor 加入已有 @testing-library/react 导入，保留 afterEach(cleanup) 和 R1，再追加：

```jsx
test('R2 成功回调后显示已保存', async () => {
  const saved = [];
  async function onRename(id, title) { saved.push({id, title}); }
  render(<ul><LessonItem item={{id: 'l1', title: 'React'}}
    onRename={onRename} /></ul>);
  fireEvent.change(screen.getByRole('textbox', {name: '课程标题'}),
    {target: {value: 'React 练习'}});
  fireEvent.click(screen.getByRole('button', {name: '保存'}));
  await waitFor(() => {
    expect(screen.getByRole('status').textContent).toBe('已保存');
  });
  expect(saved).toEqual([{id: 'l1', title: 'React 练习'}]);
  expect(screen.queryByRole('alert')).toBe(null);
});
```

执行原 Vitest 命令；不加入固定睡眠，也不改 LessonItem 的 status。

## 3～5 分钟练习

把替身接收的标题期望临时改为 Rust，确认测试失败后恢复。

## 参考答案

成功消息在完成后出现，参数包含 l1 和新标题；错误期望会失败。此替身立即兑现，尚未覆盖未完成时的禁用、父列表更新或拒绝路径。
