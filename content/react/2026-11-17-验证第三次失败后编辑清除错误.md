# 第 50 课：验证第三次失败后编辑清除错误

- 日期：2026-11-17
- 课程序号：第 50 课
- 知识点：输入变化后的错误与调用数分别断言

## 用途或适用场景

继续第49课同一R9，在第三次拒绝后编辑草稿。

## 核心概念

onChange更新草稿并清除错误，但编辑本身不触发onRename；错误消失不能代替调用数检查。

## 最小代码或操作示例

在第49课同一R9的末尾、结束大括号之前追加，保留独立first/second/third及全部既有断言：
```jsx
fireEvent.change(input, {target: {value: 'React 第四稿'}});
expect(input.value).toBe('React 第四稿');
expect(screen.queryByRole('alert')).toBeNull();
expect(input.getAttribute('aria-invalid')).toBe('false');
expect(screen.getByRole('status').textContent).toBe('');
expect(input.disabled).toBe(false);
expect(screen.getByRole('button', {name: '保存'}).disabled).toBe(false);
expect(calls).toEqual([
  ['l1', 'React 修订'],
  ['l1', 'React 第二稿'],
  ['l1', 'React 第三稿'],
]);
```
运行原Vitest R1～R9，沿afterEach(cleanup)；不重挂载或修改LessonItem，本课不提交第四稿。

## 3～5 分钟练习

错误消失后calls变成四项，是本课预期吗？

## 参考答案

不是；本课只有编辑，应仍为三次保存，新增调用要按实际来源排查。
