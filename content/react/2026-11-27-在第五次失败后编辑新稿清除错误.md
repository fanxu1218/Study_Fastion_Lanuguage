# 第 58 课：在第五次失败后编辑新稿清除错误

- 日期：2026-11-27
- 课程序号：第 58 课
- 知识点：失败后的输入变化重置交互提示

## 用途或适用场景

继续第57课同一挂载的R9，在fifth已拒绝且输入恢复后编辑。

## 核心概念

输入变化同步更新受控value，并由既有onChange清除上一轮交互错误；修改文本本身不调用onRename，不改变已保存的业务事实。

## 最小代码或操作示例

在第57课同一R9末尾追加，不新增render或受控结果：
```jsx
fireEvent.change(input, {target: {value: 'React 第六稿'}});
expect(input.value).toBe('React 第六稿');
expect(input.disabled).toBe(false);
expect(screen.queryByRole('alert')).toBeNull();
expect(screen.getByRole('status').textContent).toBe('');
expect(screen.getByRole('button', {name: '保存'}).disabled).toBe(false);
expect(calls).toEqual([
  ['l1', 'React 修订'],
  ['l1', 'React 第二稿'],
  ['l1', 'React 第三稿'],
  ['l1', 'React 第四稿'],
  ['l1', 'React 第五稿'],
]);
```
沿原fireEvent/act导入、五个独立受控结果及afterEach(cleanup)，运行Vitest R1～R9。本课不点击保存；第六稿仍为未提交输入。

## 3～5 分钟练习

输入变成第六稿后，calls能否包含第六次保存，或status显示已保存？

## 参考答案

都不能；没有提交动作，calls仍恰好五项，status为空。原错误消失只表示编辑提示重置，不表示保存成功。
