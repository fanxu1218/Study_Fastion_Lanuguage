# 第 36 课：检查可控拒绝后的交互恢复

- 日期：2026-10-28
- 课程序号：第 36 课
- 知识点：Promise拒绝后的错误与可用状态

## 用途或适用场景

Promise拒绝后的错误与可用状态，用于继续完成本路线原示例的下一步。

## 核心概念

让同一受控Promise拒绝，才能检查保存中到失败的状态转换。测试消化自己持有的Promise拒绝以完成act等待；组件仍必须显示真实错误，不能吞掉业务反馈。

## 最小代码或操作示例

在第35课R6旁追加，沿用act、cleanup、render、screen、fireEvent和waitFor导入：

```jsx
test('R7 可控拒绝后恢复输入并显示错误', async () => {
  let failSave;
  const pending = new Promise((resolve, reject) => { failSave = reject; });
  render(<ul><LessonItem item={{id: 'l1', title: 'React'}}
    onRename={() => pending} /></ul>);
  const input = screen.getByRole('textbox', {name: '课程标题'});
  fireEvent.change(input, {target: {value: 'React 修订'}});
  fireEvent.click(screen.getByRole('button', {name: '保存'}));
  expect(input.disabled).toBe(true);
  expect(screen.getByRole('button', {name: '保存中…'}).disabled).toBe(true);
  await act(async () => {
    failSave(new Error('模拟保存失败'));
    await pending.catch(() => {});
  });
  await waitFor(() => {
    expect(screen.getByRole('alert').textContent).toBe('模拟保存失败');
  });
  expect(input.disabled).toBe(false);
  expect(screen.getByRole('button', {name: '保存'}).disabled).toBe(false);
  expect(input.value).toBe('React 修订');
  expect(screen.getByRole('status').textContent).toBe('');
});
```

不修改LessonItem；catch只在测试等待中，错误内容仍由组件处理。

## 3～5 分钟练习

如果失败后组件错误显示“已保存”，本例哪项会发现？

## 参考答案

末尾status应为空的断言会失败；alert及禁用状态也要分别核对。不能只看Promise已经结束。
