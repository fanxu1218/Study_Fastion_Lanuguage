# 第 54 课：完成第四次保存并检查交互恢复

- 日期：2026-11-23
- 课程序号：第 54 课
- 知识点：独立Promise成功后恢复编辑

## 用途或适用场景

继续第53课同一个R9，让仍pending的fourth成功结束。

## 核心概念

只完成第四次保存自己的Promise；await act处理更新后，检查本次成功状态、可编辑输入与恰好四次调用，旧成功不代替当前结果。

## 最小代码或操作示例

在第53课同一R9末尾追加，沿原act导入：
```jsx
await act(async () => {
  fourth.resolve();
});
expect(calls).toEqual([
  ['l1', 'React 修订'],
  ['l1', 'React 第二稿'],
  ['l1', 'React 第三稿'],
  ['l1', 'React 第四稿'],
]);
expect(input.value).toBe('React 第四稿');
expect(input.disabled).toBe(false);
expect(screen.getByRole('button', {name: '保存'}).disabled).toBe(false);
expect(screen.queryByRole('alert')).toBeNull();
expect(screen.getByRole('status').textContent).toBe('已保存');
```
保留first/second/third/fourth、原render、回调分支和afterEach(cleanup)，运行原Vitest R1～R9；不重挂载，不再点击保存。

## 3～5 分钟练习

若误写third.resolve()，第四次pending应被当成成功吗？

## 参考答案

不应；third已属于旧调用，fourth仍未结束。只有本次独立结果处理后才能断言恢复，不能跳过pending边界。
