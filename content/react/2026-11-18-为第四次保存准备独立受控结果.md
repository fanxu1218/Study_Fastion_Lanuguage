# 第 51 课：为第四次保存准备独立受控结果

- 日期：2026-11-18
- 课程序号：第 51 课
- 知识点：每次提交对应自己的Promise

## 用途或适用场景

为第50课R9失败后编辑所得第四稿建立下一次结果来源。

## 核心概念

已拒绝的third不能再次作为新提交结果；第四次提交需独立fourth，准备Promise本身不触发保存。

## 最小代码或操作示例

只在第49、50课同一R9的third声明后，使用原辅助函数新增：
```jsx
const fourth = createControlledSave();
```
在这个R9原onRename回调中，保留calls.push以及first、second分支，只把末尾return third.promise替换为：
```jsx
if (calls.length === 3) return third.promise;
return fourth.promise;
```
保留原render与全部断言。运行Vitest R1～R9，R9仍只编辑第四稿，不点击保存、不resolve/reject第四项，不重挂载。

## 3～5 分钟练习

仅创建fourth后，R9的calls应从三项变成四项吗？

## 参考答案

不应；准备结果不调用onRename，原三次记录及第四稿编辑结果都保持。
