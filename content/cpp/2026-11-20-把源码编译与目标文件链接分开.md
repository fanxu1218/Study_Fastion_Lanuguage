# 第 53 课：把源码编译与目标文件链接分开

- 日期：2026-11-20
- 课程序号：第 53 课
- 知识点：c++的-c阶段与目标文件输入

## 用途或适用场景

让第52课观察到的链接边界成为两组明确操作。

## 核心概念

-c只生成目标文件而不链接；下一条链接命令必须包括三份目标文件。只有全部编译成功，才开始链接并运行。

## 最小代码或操作示例

在第51～52课原三源文件的个人副本目录，确认lesson53-build尚不存在，然后逐条执行：
```sh
mkdir lesson53-build
c++ -std=c++11 -UNDEBUG -c lesson.cpp -o lesson53-build/lesson.o
c++ -std=c++11 -UNDEBUG -c minutes_range.cpp -o lesson53-build/minutes_range.o
c++ -std=c++11 -UNDEBUG -c range_text_checks.cpp -o lesson53-build/range_text_checks.o
c++ lesson53-build/lesson.o lesson53-build/minutes_range.o lesson53-build/range_text_checks.o -o lesson53-build/split-checks
./lesson53-build/split-checks
```
任一条失败就停下看首个错误，不继续运行旧输出。三个源码、两个头文件与原断言均不改；输出仍为原四行且错误流为空。GCC与Clang官方均说明-c不进行链接。

## 3～5 分钟练习

最后一条链接命令遗漏range_text_checks.o，前面三条编译成功能代替它吗？

## 参考答案

不能；编译成功只生成目标文件，链接仍缺testRangeText定义。恢复该目标文件输入，不include实现文件。

## 与上一课的联系

继承第51课三源文件和第52课缺定义错误；本课只把同一构建拆为编译/链接阶段。下一课可在保留三份目标文件身份的前提下理解单文件改动的重编译范围。
